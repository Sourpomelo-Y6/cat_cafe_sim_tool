# 顧客の信頼回復イベントのADV接続

実装日：2026-10-21。既存仕様：[顧客の信頼回復と永久離脱](../../Docs/UnityStandaloneCustomerTrust.md)。判定・人気減少量・満足基準・発生条件・来店停止期限・再警告条件は変更しない。

## 接続と表示順

既存 `CafeCustomerTrust` を効果の唯一の実装とし、会話は `resolve_customer_trust` を一度送る。会話表示・読了・回想・保存読込では回答・接客判定・人気減少・経営終了判定を実行しない。実際の顧客名を表示定義から取得し、対応する警告・回答・接客結果の確定状態だけを語る。苦情の詳細、私生活、再来店・和解の会話は追加しない。

回答待ちは既存の営業停止を維持。回復を試みる回答の結果会話を読了したら、回復中だけを理由に営業・休業・日程進行を止めない。来店停止期限を短縮せず、実際の来店後に満足なら回復、普通なら継続、不満なら永久離脱。普通接客ごとの会話は作らない。

接客結果は営業中に表示せず、閉店後に表示する。永久離脱で既存の経営終了が確定した場合は、その操作内の他席の処理が完了して返された状態から表示する。営業・他席処理・閉店処理の内部には会話を挿入しない。営業中の結果待ちは `advance_business` を妨げない。既存の経営終了が営業中に起きた場合は、既存どおり営業は終了し、未実施の将来接客や閉店を新たに実行しない。

表示順は現在読んでいる会話の継続を優先し、信頼案件は警告日・ID順に処理。信頼の回答／接客結果会話→成長確認→目標結果・エンディングの順。経営終了の結末も信頼結果の後。別の共通ADVが開いている場合は割り込まず、一覧から再開する。信頼結果を閉じても未完了を保持し、営業準備・休業の不可理由に「確定済み／結果会話未完了」とイベント一覧の再開先を表示する。回復中の案内は停止理由と分ける。

## 共通UI・選択

`TrustConversationPanel` は `AcquisitionConversationPanel` を継承し、実フォントによる最大3行ページ送り、文字速度、即時表示、全文表示、次へ、バックログ、保存・読込、共通オプションを使用する。既存の客アイコン `CustomerIcon.png` をResourcesへ再配置して使用。読込不可時は共通代替表示。新規画像生成・音声・実行時LLMは使用しない。

選択の直近に以下を表示する。

- 回復を試みる：即時回復・費用・人気変化なし。来店停止期限は短縮しない。来店後の満足で回復、普通で継続、不満で永久離脱。結果会話を終えると営業・休業で日程を進められる。
- 見送る：永久離脱、今後は来店しない。人気 −既定量（現行10、下限0）、経営終了の可能性、費用なし。最終確認へ進み、取消では回答しない。

最終確認は案件IDを保持し、表示中は会話の進行入力を無効にする。確定時に確認IDを消して既存コマンドを送信。取消はゲーム状態・会話位置を変更しない。同フレーム連打防止、送信中抑制、instance/revision検査、既存回答の冪等性を併用する。

## 本文

正本は [CafeTrustDialogue.cs](../unity_preview_template/Runtime/Standalone/CafeTrustDialogue.cs) の `Lines`。以下の「顧客名」は対象警告の実名、「減少量」は既定値を埋める。

### 導入

1. 地の文：顧客名は来店停止を繰り返し、信頼警告の対象になっている。
2. あなた：顧客名への対応方針を決めましょう。回復を試みても、ここで直ちに信頼が戻るわけではありません。
3. 地の文：回復を試みる場合は、来店停止期限を変えず、来店後の接客結果を待つ。見送る場合は永久離脱となる。選択の結果を確認して決めよう。

### 回復を試みる回答

1. あなた：顧客名の信頼回復を試みます。
2. 地の文：回答は確定した。費用と人気の即時変化はなく、信頼は回復中。来店停止期限は変わらず、再来店もまだ確定していない。
3. あなた：会話を終えたら営業や休業で日程を進めましょう。来店後の接客が満足なら回復、普通なら回復中を継続、不満なら永久離脱になります。

### 見送る回答

1. あなた：顧客名の信頼回復は見送ります。
2. 地の文：顧客名の永久離脱が確定した。今後の来店対象から外れ、人気低下（減少量、下限0）と経営終了判定は反映済み。
3. あなた：この回答を記録しました。会話を終えて、店の状態を確認しましょう。

### 満足接客の回復

1. 地の文：顧客名への接客は「満足」と記録された。信頼は回復済みになった。
2. あなた：今回の接客結果を受け止めて、これからも一回ずつ丁寧に対応していきましょう。
3. 地の文：不満の値は既定の回復値へ反映済み。来店停止の累計は残るため、次の準備日に再び信頼警告が出る場合がある。

### 不満接客の永久離脱

1. 地の文：顧客名への接客は「不満」と記録された。回復中だった信頼は、永久離脱という結果になった。
2. あなた：顧客名は今後の来店対象から外れます。この結果を確認しておきましょう。
3. 地の文：永久離脱による人気低下（減少量、下限0）と経営終了判定は反映済み。この会話で再び差し引くことはない。

## 保存・互換・Extra

営業セーブ包絡v1の任意項目 `trust_conversations` と `trust_conversation_selected` を使用する。ゲームスナップショット・rules_idは変更しない。各行のキーは既存の `trust-{日}-{客ID}`。`response` と `result` は別々の節・ページ位置・完了・既読を保持する。`observe_result` は将来の接客結果を追跡する記録。会話IDは `customer.trust.v1.response` と `.result`。

保存前に実際の回答・接客結果と同期し、読込前に対象ID・重複・分岐・節・ページ位置・既読集合を検証。不正な会話メタデータで稼働中状態を置き換えない。

- 旧回答待ち：導入から新規に閲覧する。
- 旧回復中：過去の回答会話や既読を補わず、読込後に確定する接客結果だけを追跡する。日程進行を止めない。
- 旧回復済み／離脱済み：状態・履歴を維持。過去の会話・既読・未読停止を補わない。
- 新会話の途中保存：案件とフェーズの位置から復元。回答・人気低下・回復結果を再反映しない。

「会話を終える」で読了した分岐だけをExtraへ登録。解放単位は既存方式のシナリオ版＋分岐で4枠（回復を試みる、見送る、満足回復、不満離脱）。最初に読了した実名入り本文を代表として保持する。同じ分岐の全案件を別枠にはしない。営業セーブの進行は案件ごとに保持。Extraは保存本文の専用ビューで、回答コマンド・信頼・人気・日付を変更しない。

## 残る課題

標準条件で警告発生まで遊ぶ長期バランス評価、全客・全解像度・他イベントとの全組み合わせは後続。回復直後も累積来店停止により再警告する既存仕様を維持。Extraは各分岐の代表本文で、過去の全案件を網羅する機能ではない。異なるrules_idや旧Python保存の変換対象は従来のまま。
