# 開発専用・観戦自動プレイ

2026-10-30。通常画面でプレイの様子を見ながら進める開発用モード。[内部の9ルート収集検証](DeveloperAcquisitionCollection.md)は比較用に残し、起動・保存・結果を分けた。通常のおまかせやゲーム係数は変更せず、公開必須条件へ追加しない。

## 使い方

現在の固定Latestがこの機能を含む専用Playerなら、作業ルートのPowerShellで次を実行する。

```powershell
cd C:\Users\hi-wa\source\codex_repos\CatCafeSim
.\cat_cafe_sim_tool\run_dev_watch.ps1
```

通常のタイトル画面と、右上の「開発専用・観戦自動プレイ」操作欄が表示される。「実行・再開」でタイトルから自動操作を始める。最初から走らせる場合は `-Start` を付ける。

|操作|動作|
|---|---|
|実行・再開 / 一時停止|次の画面操作を実行／停止。すでに送った通常処理は確定境界まで完了する|
|1操作|停止状態で、画面上の操作を1つだけ進める。会話では全文表示・次のページ・回答の確認等を1つずつ進める|
|1倍・2倍・4倍|営業や画面遷移の間隔を変更する。ゲーム係数やUnityのtimeScaleは変えない|
|会話短縮：入／切|切では通常の文字表示を待ち、本文を読める間を取る。入では既存「全文表示／次へ」を短い間隔で操作する|
|たたむ / 開く|操作欄を小さくして画面を見やすくする|
|操作欄の見出しをドラッグ|好きな場所へ操作欄を移動する|
|保存して終了|検証専用スロット9へ営業と会話位置を保存して終了。完走後は「終了」になる|

次の行動と理由を操作前に表示する。通常速度は1操作の待ち時間0.8秒、会話は文字表示後さらに1.6秒を基準にする。倍速は待ち時間へ適用し、通常の文字表示速度設定は変更しない。

保存した実行フォルダーを指定して再開する：

```powershell
.\cat_cafe_sim_tool\run_dev_watch.ps1 -ResumeDirectory "C:\...\Logs\DeveloperWatch\Runs\実行ID"
```

再開では通常タイトルのロード処理を使って営業・会話を復元し、停止状態で待つ。実行を押すまで新しいゲーム操作を進めない。ロード操作自体は操作記録に残る。自動で続ける場合は `-Start` を追加する。同じビルド・ルール・素材でのみ再開可能。

その他：`-Speed 2`、`-Speed 4`、`-ShortDialogue`、`-Days 4`～`8`、`-Wait`。16倍は検証用の高速起動オプションで、通常の画面ボタンには置かない。`-ExitOnComplete` は完走・保存後にPlayerを自動終了する検証用オプション。

## 今回できる範囲

人気目標を通常条件で新規開始し、オープニング→営業準備→出勤・休養案の確認→接客→閉店結果→翌日→依頼/店舗イベント/常連紹介の会話を進める縦断ルート。既定は8日分の営業を終え、9日目の準備で保存・停止する。人気目標のクリア、9収集ルートの画面操作、全31猫・全回想・全画像の獲得完了ではない。

初版は4～8日の観戦用範囲に限定する。UI上で未対応の回答が必要なら、選択や状態を勝手に書き換えず、理由を残して止める。自動操作は10000コマンド、同じ進捗の待機は120秒を上限とする。ユーザーが停止して待つ時間は進行待ちの上限に含めない。

## 操作と保存の境界

- 通常のタイトル、準備、会話、成長、接客、閉店等の画面部品とハンドラーを使う。内部runnerの独立simulationを裏で走らせて画面だけ更新する方式ではない。
- 営業は通常ボタンのonClick、会話は通常Next/回答/最終確認を使用する。出勤案も通常の案作成・確定を順番に操作する。通常のおまかせや自動進行を起動して一気に進めない。
- 会話の公開参照は位置/選択待ち/本文表示済み/対象panelの読み取りのみ。ゲーム状態や会話node、資金、XP、フラグ、既読を直接変更しない。
- 会話を閉じた後はイベント一覧から営業画面へ戻り、閉店結果や翌日の準備を画面で確認してから次へ進む。裏側のボタンだけを押して営業を続けない。
- 各runの `profile/standalone-v1` 内に通常形式のセーブ、Extra、CG、既読等を保存する。設定・営業ログもrun配下。通常profileと祖先/子孫関係のあるパスやリンク、他のQA/HTTP/profile引数との併用を拒否する。
- 通常ビルドでは `CATCAFE_DEV_ACQUISITION` 定義がなく、観戦runnerは含まれない。専用ビルドでも引数がなければ作動しない。

専用Playerが必要な場合の再ビルドは従来の固定Latest入口を使う。

```powershell
cat_cafe_sim_tool/build_standalone.ps1 -ProjectPath C:/Users/hi-wa/unity_workspase/CatCafeSim -ExecuteMethod CatCafePreview.Editor.DevAcquisitionSetup.Build
```

## 保存先と結果

起動時に表示される `Watch run:` のフォルダー（`Logs/DeveloperWatch/Runs/<id>`）を参照する。

|ファイル|内容|
|---|---|
|watch-plan.json|観戦日数、開始目標、実行ビルド・ルール・素材入力の識別|
|watch-status.json|現在の停止/実行/完走、日/刻、次の操作理由、会話位置、UI操作・通常コマンド数、通常の回想/画像閲覧記録|
|watch-ui-actions.jsonl|画面上で実行した操作と会話位置|
|watch-commands.jsonl|通常バックエンドへ送った操作、応答エラー、状態digest|
|watch-checkpoint.json|正常保存のSHA、会話位置、状態digest。再開前に照合する|
|profile/standalone-v1/slot-9.json|通常バックエンドが保存した完全なゲーム・会話状態|

`watch-status.json` のlayerは `ui-handlers`。通常の回想・CG記録を読み出すが、全解放やカタログの一括既読は行わない。UIハンドラーによる自動操作と、Windows実入力で全ルートを操作する検証は区別する。`physical_input_verified` は全自動経路を物理入力確認と誤認させないためfalseのまま。

外部の検証からrun直下に `pause.request` を置くと、次の確定境界で停止・保存する。通常利用では画面の「保存して終了」を使う。ウィンドウの×による終了では新規の保存要求を送らないため、再開したい場合は保存操作を使う。

## 検証と後続

Runtime+Editorの専用defineあり/通常defineなしの参照コンパイル成功。Windows Playerでタイトル、開始条件、オープニング、営業、ナナの会話を表示。実入力で1操作、一時停止、倍率変更、折りたたみ・展開、保存終了を確認した。会話途中の保存を別プロセスで読み、同じ台詞と位置へ戻ることも画面で確認。

最初の画面確認では、会話後のイベント一覧を開いたまま営業の操作が進む箇所を修正。再開直後には画面復元前の記録が残る箇所があり、停止中も画面位置の確定を記録へ反映するよう修正した。

最終Playerの完走・再開結果と容量は後記する。全収集ルートへのUI対応、購入・派遣・猫交流の観戦、長期目標達成、多数乱数、全会話分岐、全画像の画面確認は後続。今回の完走をそれらの完了には数えない。

UI操作数とUIログのsequenceは現プロセスのカウンターで、再起動時に0から始まる。通常コマンド数はcheckpointから継続し、ゲームの進行・獲得判定はログ行数ではなく通常の保存状態と閲覧記録を使う。

## 最終Playerの結果

- 中断なし：`Runs/20261030-190725-5652873b22a64dec81901abb31c1e466`。8日分の営業を終え、9日目0刻に保存・終了0。

- 再開後も9日目0刻へ完走。最終の通常状態digest `742057522db322227169fcb4032db9e2043a667726d144d11cf3f2647e16aa64` が中断なしと一致。通常の回想キー4件・画像閲覧キー7件も集合一致。これは8日コースのUI経路で到達した記録であり、全回想・全画像の収集数ではない。
