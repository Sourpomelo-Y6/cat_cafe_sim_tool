# 日常交流文のローカルLLM生成（第2段階）

2026-10-15実装。[編集・保存画面](InteractionTextEditor.md)に、選択条件を使った3案生成と選択取り込みを追加した。画像付きプレビュー、Unity書き出し、ゲーム内の候補選択は後続。

同日追補：[画像付きプレビューと採用済み交流文の書き出し](InteractionPreviewExport.md)を追加した。以下は第2段階の記録。Unityでのカタログ取り込み・ゲーム内候補選択は引き続き後続。

## 操作

1. 制作ツールの「日常交流の文章を編集…」で人物／猫・行動・操作・反応を選ぶ。
2. 「ローカルLLMで3案生成…」を押す。開いた画面の対象・条件・画像キーを確認する。別の条件で生成するときは生成画面を閉じて開き直す。
3. 接続先を確認し、「モデル一覧を取得」からモデルを選ぶ。初期値は `http://127.0.0.1:8080`。モデル名の直接入力も可能。
4. 「生成に使う資料」タブに、人物の口調・設定、または猫の特徴・性格、対応する絵の状態、文章の希望を入力する。名前だけから性格を創作せず、未設定の事項は書かせない。画像は送信しない。
5. 「接続・資料の設定を保存」で次回に入力を引き継げる。保存は明示操作であり、生成・閉じるだけでは設定を保存しない。
6. 「この条件で3案生成」を押す。完了すると「生成した3案・取り込み先」タブへ切り替わる。
7. 取り込む案にチェックし、それぞれの取り込み先を案1〜3から選び、「選択した案を編集欄へ取り込む」を押す。取り込まない欄は保持する。複数案に同じ取り込み先は指定できない。
8. 編集画面で文章を校正し、下書き保存・登録内容の確認・確認した文章の登録へ進む。生成や取り込みだけでは、下書き・採用済み素材を保存しない。

人物のセリフと猫の反応は別生成する。現在の対象はプレイヤー・佐藤さん・ミケ、ねこじゃらし・なでる・休憩。人物の自由登録やプロフィールのゲームへの反映は追加していない。

## 接続・生成・保護

`InteractionLlmClient` は既存 `LlmClient` の接続先検証・モデル一覧・HTTP処理を再利用する。既存の紹介文＋4場面の生成処理・プロンプトは変更しない。非同期処理と閉じた後の結果破棄も既存の生成画面と共有し、回答の表示と取り込みは交流文専用とする。

送信条件はツールが確定する。対象・行動・操作・反応・画像キーと資料をプロンプトへ渡し、モデルには `variants` に本文3つだけを持つJSONを返させる。モデルが条件やIDを追加した応答は受け付けない。各案の空欄・200文字上限・制御文字・重複・出力中断を検証し、取り込み時には残した既存案との重複も確認する。反応の正しさをモデルに決定させない。

起動中のllama.cpp系サーバーに合わせ、3要素のJSON Schemaと `chat_template_kwargs.enable_thinking=false` を指定する。最初の実モデル確認ではJSON形式だけの指定で3案が1つの文字列になり、既定の思考処理で出力上限に達するケースもあったため、この指定を加えた。接続先にはこの指定を扱えるサーバーを使う。別の互換サーバーでの動作は未検証で、未対応時はエラーを表示し、既存文章を維持する。

人物の発話はかぎ括弧・行動説明を含めないよう依頼する。猫の反応は猫を主語にした常体の過去形とし、「あなた」「飼い主」を使わず、接客にも個別交流にも使える表現を依頼する。これは生成指示であり、形式検証だけで内容の自然さ・絵との整合を保証するものではない。

生成待ちを含め、生成画面を開いた後に編集本文や対象条件が変わった場合は取り込みを拒否する。成功した選択取り込みの後は、その状態を次の取り込みの基準にできる。取り込み後は登録内容の再確認が必要。画面を閉じると受け取りを中止するが、サーバーの処理停止APIは呼ばない。モデル一覧は15秒、生成は180秒を応答待ち上限とする。

## 保存先

- 設定：`user_data/interaction_llm_settings.json`。接続先・モデル・文章の希望は共通、人物／猫の資料は対象IDごと、絵のメモは文章条件ごとに保持する。不正な既存設定は上書きしない。
- 生成記録：`generated/interaction_texts/<UUID>.json`。対象条件、接続先、モデル、入力・生成指示、API応答、検証済み3案、生成日時を保存する。採用やゲーム反映を意味しない。
- 下書き・登録先：第1段階の交流文ファイルを維持する。既存の紹介文、画像、ゲームセーブには書き込まない。

## 検証結果

専用10テスト（データ・通信条件4、実Tk画面6）が成功。3案JSONの検証、条件・資料の送信、生成記録、無効な入力・中断・キャンセル、設定の対象別保持と不正ファイル保護を確認した。GUIでは一部だけの取り込み、取り込み先の重複拒否、本文・条件変更後の取り込み拒否、既存案との重複拒否、未確認登録の拒否、設定再開、遅れて届く結果の破棄、通信・応答エラーの表示、740×670で両タブの文章欄と取り込みボタンが収まることを確認した。

既存31テスト（編集・保存17、紹介文LLM4、紹介文編集2、画像制作ツール8）も成功。既存GUIテストの終了時にTkのThemeChanged通知が出るケースがあるが、テストは成功している。

起動済みのGemma 4 12B Q4_K_Mモデルに実接続し、次の4条件で各3案の生成→編集欄へ取り込み→確認前の登録拒否→確認後の検証用登録→保存内容一致まで成功した。

[実モデルの生成例と検証範囲](Results/InteractionLlmGeneration.json)を記録した。生成例には「眠りながら待つ」「手から放たれる動き」など校正すべき表現もあり、これらを無条件にゲーム用として採用してはいけない。形式・保存・取り込みの成功と、文章品質の採用判断は区別する。検証用登録はテスト用フォルダだけに行い、ユーザーの制作素材やゲームには登録していない。

再現は制作ツールのフォルダで行う。

```powershell
$env:CAT_CAFE_TEST_GUI='1'
$env:PYTHONUTF8='1'
python -m unittest discover -s tests -p test_interaction_llm.py -v
python verify_interaction_llm.py --output ../Logs/InteractionLlm/live-check
```

実接続には起動済みローカルサーバーとTk画面が必要。検証プログラムは指定したフォルダにのみ設定・下書き・検証用登録・生成記録を保存する。今回の最終実接続結果は `Logs/InteractionLlm/live-final`。制限環境でローカル接続が拒否されたため、通常環境で接続して確認した。単体テストの一時ファイルはワークスペース内の `Logs/InteractionLlm/temp` を `TEMP`／`TMP` に指定した。

Unityビルド・プロジェクトコピー・Library追加は行っていない。検証のログと少量の文章JSONだけを追加し、既存のビルドや素材は変更していない。
