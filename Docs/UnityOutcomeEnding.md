# 目標未達・経営終了の短い結末

2026-10-20。期限・費用・目標・経営終了条件・配布ルールは変更しない。

## 現行条件と操作

| 条件 | 確定処理と、その後の操作 |
| --- | --- |
| 人気目標 | 各段階の閉店時、人気が目標以上なら達成。それ以外で期限に到達すると expired。未達後も結果確認を経て自由営業を続けられる。次の人気段階は成功時だけ |
| 好感度・有力者・自由営業 | 期限未達を新設しない。成功3系統は既存のまま |
| 経営終了 | CheckEndが資金0以下を優先し、次に人気0以下を判定。営業再開は禁止。保存・ロード・タイトル復帰・結果閲覧は可能 |
| 期限日と経営終了が重なる | CloseはCheckEnd→SettleGoalの順。終了済みならSettleGoalは何もしない。会話も確定した経営終了だけを扱い、expiredを創作しない |

根拠はRuntime/Standalone/CafeSimulation.cs、CafeExpansion.cs、CafeClearResults.cs。新規の失敗条件はない。未達・終了会話の読了を経ても、既存の回答待ちや営業段階による操作制限は維持する。

## 演出・本文

正本は `unity_preview_template/Runtime/Standalone/CafeOutcome.cs`。安定IDは `ending.outcome.v1`、分岐はexpired / funds / popularity。成功と異なる見出しでExtraのエンディング一覧に3本追加する。

1. 地の文「あなたはカフェの記録を開き、今回の結果を静かに確かめました。」
2. 営業の記録：人気未達なら段階・期限と未達確定、資金不足なら「資金が0以下になり、経営終了が確定しました。」、人気低下なら「人気が0以下になり、経営終了が確定しました。」
3. 営業の記録：確定日・資金・人気・在籍数・当日の接客売上。人気目標がある場合だけ段階・目標値・期限。すでに未達記録が存在した後に終了した場合は、その確定日の記録も添える。同日の未確定状態から未達を補わない。
4. あなた「思い描いた結果には届かなかったね。／それでも、ここで向き合ってきた時間まで、なくなるわけではない。」
5. 未達「今回の挑戦は、ここでひと区切りです。／結果を確認したあとは、猫や資金を引き継いで営業を続けられます。」、終了「今回の経営は、ここで終わりを迎えました。／今はこの記録を、ゆっくり受け止めましょう。」

「／」は改行。借金・売却・猫の行き先など未設定の出来事は語らない。猫の現所在を推測せず、共通の店内背景と画像欠落時の代替表示を使用する。新規画像・音声・実行時LLMは追加しない。

共通AcquisitionConversationPanelを継承し、最大3行のページ送り・全文表示・次へ・バックログ・保存・オプションを共用する。閉じると既存結果画面へ戻り、未達は既存の再開ボタン、経営終了は追加の「結末を再開」から保存位置へ戻る。読了後は既存結果画面。営業は自動再開しない。

経営終了が表示上の最優先。未達は既存のrequired_action、他会話、成長候補の優先を尊重する。未読のcontinue_goalをバックエンド・UI双方で止める。他目標の結果確認は止めない。おまかせのstep_autoplayは既存の終了処理を完了できる。会話自身は営業・報酬・目標判定を実行しない。

## 保存と互換方針

保存形式1の任意フィールドoutcomeへ、確定時の原因・数値とprogressを保持する。営業状態の形式・ダイジェストは変更しない。閉店コールバックは既存の日別記録コールバックを呼んだ後、休業の翌日移行より前に固定値を捕捉する。ほかの終了操作も応答生成時までに捕捉する。同じ結果は再表示やロードで再生成しない。未達から継続した後に経営終了した場合は、新たな原因の会話を提供する。

| 保存状態 | 対応 |
| --- | --- |
| 旧セーブの通常進行中 | 結末を作らない |
| 旧セーブの未達・結果未確認 | 未読で先頭から。欠けている確定時スナップショットを創作せず「旧セーブから確認できる記録」と明記して、読込時点の保存状態を固定する |
| 旧セーブの未達・継続確認済み | 進行を止め直さない。Extraを解放しない |
| 旧セーブの終了済み | 未読で先頭から。「旧セーブから確認できる記録」と明記。読了後も営業再開不可 |
| 新形式の会話途中 | node・page_offsetを復元。閉じる／タイトル復帰後のロードでも同じ位置 |
| 新形式の読了済み | 既存結果画面。実際の読了情報だけExtraへ取り込む |

未設定参照を空オブジェクトとして返すUnity JsonUtilityは既存会話と同様に未設定へ正規化する。会話ID・分岐・位置・読了と閲覧分岐の整合・数値の有限性などを検証する。Extraは独立extra-v1.jsonへ読了時のみ登録。初回登録時の本文を保存し、回想は営業状態やスロットをロードせず、コマンドも実行しない。新規開始や古いスロットのロードで既存解放を消さない。
