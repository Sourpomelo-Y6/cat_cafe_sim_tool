# 好感度目標の成功エンディング

2026-10-19実装。目標条件・好感度係数・報酬・通常ルールのバランスは変更しない。

## 構成と仕様

好感度達成の既存 `CafeClearRecord(mode=bond)` と `bond_goal.achieved_cats` を利用する。達成日、目標猫数、達成猫数、在籍数、資金、累計接客売上は固定記録から表示する。継続営業後の現在値で上書きしない。

本文は `Runtime/Standalone/CafeBondEnding.cs` の `Lines` が正本。達成猫一覧の先頭から実際の猫データに存在するIDを選んで保存し、プロフィールの名前・既存画像を使う。画像未登録は既存シルエット、背景は共通の店内代替表示。猫の現在位置に依存しない「記録に名前がある」という表現で、譲渡・派遣などで不在になっても目の前にいるとは書かない。記録にない過去・行動・固有の思い出は追加しない。

人気版の `CafeEndingProgress`、`PopularityEndingPanel`、`AcquisitionConversationPanel`、保存ブラウザ、オプション、`CafeReplayStore`、`ReplayConversationPanel` を共用する。好感度固有なのは本文、安定ID `ending.bond.v1/cleared`、達成猫の選出と保存項目のみ。全文表示、次へ、バックログ、オプション、本文3行ページ送りを共通実装から利用する。新規画像・音声・実行時LLM・猫別量産は行わない。

閉じると結果画面の「エンディングを再開」で同じ位置へ戻る。読了後は固定成果と「保存」「継続営業」「タイトルへ」を表示する。保存は既存ブラウザ、継続は既存 `continue_bond_goal` を呼ぶ。会話は報酬や継続を直接実行しない。継続前の未読チェックはUIとバックエンドの両方で行い、別目標の結果確認は妨げない。通常のコマンドID／リビジョン検証により連打と再送の重複処理を防ぐ。

成長候補がある間、別会話が開いている間、好感度結果より優先する required_action がある間は自動表示しない。おまかせの終了処理 `step_autoplay` は未読制限から除外し、達成時に通常の停止処理を完了できる。会話と読了画面から営業・自動進行を勝手に再開しない。

## 本文

1. 地の文：あなたはカフェで、猫たちとの関係を記した記録を開きました。／数字の向こうに、それぞれの猫と向き合う時間があります。
2. あなた：好感度の目標を達成できたんだね。／猫たちとの距離が、少しずつ近づいてきたんだ。
3. 地の文：達成した猫の記録には、{プロフィールの猫名}の名前もあります。／あなたはその名前に、そっと目を留めました。猫が選べない場合は「達成した猫たちの記録を、ゆっくり読み返します。」。
4. あなた：一緒に過ごす時間を、これからも大切にしたい。／その子の様子を見て、無理をせずに向き合っていこう。
5. 営業の記録：達成日、目標猫数、達成猫数、達成時の在籍猫・所持金・累計接客売上。「これは目標達成時に記録した成果です。」。
6. あなた：目標は、ひとつの区切り。／これからの毎日も、猫たちの気持ちを大切にしていこう。
7. 地の文：猫たちとあなたの間に育った関係。／そのつながりを大切にしながら、カフェの日々は続いていきます。

「／」は本文内の改行。長い行は共通ページ処理で3行ずつ送る。

## 保存と旧セーブの互換方針

営業セーブ形式1の任意項目 `bond_ending` に猫IDと会話進行を追加する。会話ID・分岐・node・page_offset・completed・viewed_branchesを共通検証し、猫IDは達成猫一覧にも属することを確認する。ゲーム状態のダイジェストや係数は変えない。Unityが未設定の参照型を空オブジェクトとして出す場合は、他会話と同様に未設定へ正規化する。

| 旧データの状態 | 方針 |
| --- | --- |
| 目標が進行中／達成記録なし | 成功演出を作らない。欠けた成果を現在値で補完しない |
| 固定達成記録があり結果未確認（continued=false）、会話情報なし | 先頭から演出を提供し、未閲覧として扱う |
| 既に継続済み（continued=true）、会話情報なし | 演出を強制せず、進行を再び止めない。Extraは解放しない |
| 会話途中の新形式 | 保存した猫ID・本文位置・ページ位置を復元 |
| 読了済みの新形式 | 読了成果画面を復元。閲覧完了が実在する場合のみExtraへ取り込む |

Extraは既存の独立した `extra-v1.json` へ最後まで読んだ時だけ追加する。「エンディング」分類に人気・好感度の2本を表示する。保存スロットやバックアップから実際の閲覧完了記録を取り込める。新規ゲーム・古いスロットロードは既存の解放を消さず、同じ安定IDを重複追加しない。回想は保存操作も営業コマンドも持たない読み取り専用。営業セーブを読み込まず、初回登録時の本文・猫表示・固定成果を使う。

## 検証記録

検証は `Logs/StandaloneBondEnding` に保存する。専用ルール複製で目標猫数1、必要好感度0.1などに短縮し、通常の新規開始・交流・達成判定を通す。通常セーブ・通常Extraへ書き込まない。オプション画面は確認後に変更を取り消し、通常設定へ書き込まない。標準6匹の長期達成日やバランスは今回の検証対象外。

Editor検証は好感度35件・既存人気22件が成功。共通会話の.NET回帰430 assertionsも成功。配布版の初回51件・別プロセス再起動53件は成功し、Unityエラー0件。最終版は初回51件・別プロセス再起動55件が成功。読了済み・旧継続済みの別プロセス復元チェックも通過した。

自動検証は、通常の交流から達成→未読時の継続拒否→各nodeとpage_offsetの保存復元→読了→重複登録防止→継続→固定成果不変、旧未確認／旧継続済み、無効位置、新規ゲームのExtra保持、猫の選出、譲渡前後の保存復元、おまかせ停止・ロードを含む。達成後に実際の営業・譲渡コマンドで達成猫を譲渡し、猫ID・読了・固定記録が維持されることを確認した。

複数未確認目標の重なりは、通常UIが次の進行を制限するため合成データで好感度→人気の順に確認した。成長・未回答譲渡・派遣帰還の表示優先も投影した状態による合成検証。閉店後成長処理自体は通常の休業・一括確定で確認し、好感度の交流達成は通常の営業準備中に行った。標準ルールの長期同時発生を実プレイで再現したという意味ではない。

配布版1024×768をcomputer-useで操作した。閉じる→結果画面から再開、設定を開く→変更せず戻る、次へ、固定成果の3行＋次ページ、会話の2ページ目で保存ブラウザ→空きスロット2へ確定保存（node=4 / page_offset=69）、読了成果画面、タイトル復帰、Extraのエンディング1/2表示→好感度回想→閉じる、タイトルから読了済みスロット7をロード→成果画面→継続営業を確認した。画像・本文・成果・ボタンに欠けは見られなかった。初回1280×800は自動UI検証で確認。実画面のスクリーンショットは今回チャットの操作記録に残る。

証跡：`Editor/result.txt`、`core-result.txt`、`Player/result-first.txt`、`Player/result-restart.txt`、各Playerログ、専用casesとui-*のセーブ／Extra。実装途中の失敗ビルドログもRunsに残す。最初のライセンスIPCエラーはサンドボックス外で解消、コンパイル時の置換ミスを修正した。追加fixtureの目標開始、譲渡コマンドの出勤指定、譲渡成立までの営業日数、無関係な加入イベントの問題を直した後に再実行している。
