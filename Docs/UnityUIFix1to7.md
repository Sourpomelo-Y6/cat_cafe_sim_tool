# Unity UI修正1～7の調査・検証

実施日：2026-10-19。対象はワークスペースの `Docs/UnityUIFixRequests.md` の1～7。項目8の閉店後集約・猫別自動決定は実装しない。

## 調査と修正

| 項目 | 原因・既存実装 | 今回の対応 |
| --- | --- | --- |
| 1 | 休養・派遣の効果データは既に存在した。非表示中に選択肢数が変わると、親ScrollRectを取得できず、説明のTextだけを非表示にする経路があった。次の表示で親だけを復帰してもTextは戻らない。 | 非表示の親も検索し、説明Textと親の表示状態をともに復帰する。効果や費用の数値は変更しない。 |
| 2 | 保存・再読込時のおまかせは `running=true, paused=true`。上部はローカル実行フラグで一時停止と表示するが、回答UIとバックエンドはrunningだけを見て拒否していた。エンディングなしでも成長待ち直後に保存すると再現する。 | 実行記録の存続と実際の進行を分け、一時停止中は成長回答・会話・結果確認を許可する。回答は自動再開しない。成長未回答の再開をUI・シミュレーションの両方で防ぐ。営業日の更新は再開／中止まで禁止し、おまかせの日数記録を維持する。エンディングは成長待ちを覆わず、回答後に開く。 |
| 3 | 人気エンディングとExtraは既存のAcquisitionConversationPanelを共用。元の会話1ノードに4行以上の本文が入り、本文ScrollRectを前提にしていた。 | 同じフォント・本文幅・折り返し設定のTextGeneratorで最大3行を抽出する。人気エンディングとその回想だけに適用する。本文スクロールと小さな注釈を外し、3行分の高さを確保する。元の会話ノードは維持し、ノード内の文字位置page_offsetを保存する。 |
| 4 | 目標表示用の共通投影には達成済み人気目標も残る。これをそのまま営業画面右側へ表示していた。 | 右側用の投影sidebar_progressを分け、達成済み人気目標だけを省く。既存の共通投影、別目標、達成記録、閉店結果での閲覧は維持する。 |
| 5 | 制作プレビュー由来のDisplayPythonCatが、最後に選択された猫の紹介・行動・状態を営業画面右側へ描画していた。 | 営業画面の常設本文から選択猫の文章を外す。猫カード・猫詳細・接客客一覧は維持する。 |
| 6 | 加入確認後のjoinedEntryを、おまかせ領域に常設表示していた。 | この常設ショートカットを非表示にする。加入記録や猫詳細への本来の導線は維持する。 |
| 7 | セーブ等の上段とメニュー等の下段が別々の座標・幅で設定されていた。件数ラベルもフォント設定が競合した。 | 共通の148×38、横間隔4・縦間隔2の3列×2段に固定する。件数ラベルは2行・枠内で縮小表示し、文字長でボタン幅を変えない。 |

## 会話と保存の互換性

- `ending.popularity.v1`、分岐ID、シナリオ配列のノード数、Extraの解放キーは変更しない。
- 追加したpage_offsetは表示専用の整数。旧セーブでは0となり、従来のノード先頭から再開する。新しい保存はページ途中の位置も保持する。
- 「全文表示」は現在のページを表示し、「次へ」で同じノード内の次ページへ進む。ノード末尾まで読んでから次のノードへ移る。文字速度・即時表示は既存の設定を使用する。
- バックログには通過したノードと現在までのページを表示する。回想でも同じページ処理を使い、営業状態や閲覧済み記録を書き換えない。
- 成長の必要経験、適用時期、効果、最大体力成長、営業・人気・派遣等の数値は変更しない。加速条件は検証専用のルール複製に限定する。
