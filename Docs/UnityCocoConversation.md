# 来訪猫ココの初対面・加入ADV

実装日：2026-10-22。対象はUnity単独版。日次交流を長いADVにせず、初対面と加入相談だけを共通会話へ接続する。

## 仕様・既存ルール

人気第1段階達成の翌準備日から出現。無料・準備中1日1回の店先交流を3回行うと加入可能。同日の3回目直後にも加入できる。日次の「今日は見送る」は当日の交流枠を消費し、進捗を保持する。プレイヤー交流のセット数・好感度とは別である。

初対面は出現後に一度。ページ位置を保存し、閉じた場合はイベント一覧の店先から再開する。読了後は日次画面へ戻る。加入可能時に導入→迎える／今回は迎えない→結果。「今回は迎えない」は会話内の保留で、日次枠・候補・進捗・資金を変更しない。結果を読み終えてから、店先の迎える操作で何度でも再相談できる。恒久拒否は追加しない。

加入前に既存DTOから費用・所持金・残金・現在数／上限・健康体力全回復・疲労ストレス好感度0・休養予定を表示する。費用200、支払後に資金が残る必要があり200不可／201可、空き飼育枠必須。加入は既存resolve_visiting_cat／JoinCat、日次交流・見送りも既存処理のまま。加入の最終確認取消は無変更。資金・枠不足でも閉じて通常準備に戻れる。

任意会話の未読・途中結果だけでは営業／休業を止めない。他の必須会話・回答待ちがある場合はそちらを優先し、共通会話同士の開閉調整を使う。営業中・閉店中・経営終了中には店先ADVを自動表示しない。再開は準備画面から行う。

## 本文とプロフィール

確定設定はココ、visiting-cat-1、距離を大切にする猫、のんびり屋。外見の正本はpresentation.jsonの詳細プロフィール（キジトラ・短毛・琥珀色の目）。旧資料UnityStandaloneVisitingCat.mdには旧設定の「茶トラ」が残るため、本文では外見を断定しない。飼い主・過去・店先に来る理由は未設定のまま。

初対面：

- 地の文「店先に、ココが姿を見せた。少し距離を置いて、こちらを見ている。」
- あなた「ココ。今はここから、こんにちは。近づきすぎず、少しずつ慣れてもらいましょう。」
- 地の文「ココは距離を大切にする、のんびり屋の猫。店先での交流は無料で、準備中に1日1回。必要な回数は店先の交流画面で確認できる。プレイヤー交流のセット数とは別の記録だ。交流せず営業や休業へ進んでも、これまでの進捗は残る。」

加入導入：

- 地の文「交流を重ね、ココはこの店先に十分慣れている。迎えるための準備を確かめよう。」
- あなた「ココのペースは、これからも大切にしたい。費用と飼育スペースを確認して、迎えるか決めましょう。」
- 地の文「今は迎えなくても、候補と交流の記録は残ります。資金や飼育枠が足りなければ、閉じて通常の準備に戻れます。」

迎える結果：

- あなた「ココ、ようこそ。ここでも、少しずつ慣れていこうね。」
- 地の文：実際の費用と精算後の残金を確定時に保存し、健康・体力全回復、疲労・ストレス・プレイヤー好感度0、休養予定で加入したことを表示する。
- 地の文「店先で重ねた交流は、加入の記録として残った。出勤するか休養するかは、営業準備の猫一覧から選べる。」

今回は迎えない結果：

- あなた「今回は、まだ迎えずにおきましょう。また準備ができたときに。」
- 地の文「ココは引き続き店先の候補です。交流進捗・資金・飼育枠は変わりません。今日の交流や見送りの回数も消費しません。店先の画面から、いつでも迎える相談を再開できます。」

日次交流・見送りは既存の短文・確認と履歴表示を継続。AcquisitionConversationPanelの最大3行ページ送り、文字速度、全文表示、次へ、バックログ、保存・読込、オプションを使用。新規画像・音声・実行時LLMはない。

実素材はAssets/Resources/CatCafeContent/catalog.jsonが参照するImports/4762dd1bd978461bb07c041c59417281/bundle.jsonのvisiting-cat-1、normal画像images/7689d60b37e3b2aecb55995659da1b8576a542bf515afb10c574fbea332eb486.png。CandidateCatTextureにより読み込み、未登録・取得不可の場合は既存シルエットにする。

## 保存・互換・Extra

包絡v1に任意のcoco_conversations配列を追加。初対面はattempt=0、加入相談は1から連番。conversation_id、branch_id、node、page_offset、completed、viewed_branches、加入後の精算結果を保存する。日次回数・加入・費用はゲーム状態側の既存履歴で管理し、会話の読了では再適用しない。既存request_id／expected_revision・コマンド実行可否・共通会話の同一フレームガード・最終確認を再利用する。

旧セーブは欠落配列を許容する。出現前は会話なし、未加入の交流途中／加入可能なら未読の初対面と現在必要な加入相談を用意する。過去に読んだとは扱わず、Extraは未解放。加入済みで記録がなければ初対面・加入結果を新造しない。既存のルール識別子互換条件は変更しない。

Extra解放単位はcoco.meeting.v1/meeting、coco.admission.v1/accepted、coco.admission.v1/laterの3件。実際に最後まで読んだ分だけを登録。反復する保留は営業セーブには試行別に保持するが、Extraは同じlater分岐1件に統合する。回想は専用の進行コピーと保存済み本文で再生し、日次回数・候補・進捗・加入・費用を変えない。
