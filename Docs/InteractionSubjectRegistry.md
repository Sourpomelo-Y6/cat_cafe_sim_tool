# 猫・お客さんを追加して交流文を制作する

2026-10-16実装。[設計案](InteractionSubjectRegistryPlan.md)の対象台帳、登録画面、多対象の編集・生成・プレビュー・Unity連携に対応。

## 操作

1. 「猫の素材制作」→「対象管理」→「猫・人物の登録と資料…」を開く。
2. 「猫」または「人物・お客さん」を選ぶ。タマや鈴木さんなどは一覧から「既存対象から追加」。まだゲームに登場しない対象は「制作専用の対象を追加」を使う。
3. 表示名・資料を確認して「対象と資料を保存」。猫には既存の性格・外見資料を初期入力する。新しい人物の口調・接し方は資料欄に入力する。名前から設定を推測して生成しない。
4. 交流文編集で追加対象を選ぶ。人物は適用範囲も選ぶ。「どの猫でも使う」は `{cat_call}`、猫の反応文は `{cat}` を使う。呼び名は人物の台帳で `{cat}ちゃん` などと設定する。
5. 連続生成では現在の対象だけを初期選択する。他の対象も選択できる。操作別を含める場合は「共通＋操作別」。猫は反応条件も選べる。対象一覧はスクロールできる。
6. 「未入力の条件だけ生成」は1案でもある条件を保護する。「3案未満の空欄を補う」は既存案を資料に添え、空欄だけに別案を補う。既存案が生成後に変わった場合は取り込みを止める。
7. 生成結果を1条件ずつ編集欄へ取り込み、下書き保存→登録内容を確認→確認した文章を登録。生成だけでは本文を登録しない。
8. 画像付きプレビューで対象猫と人物を選び、名前・反応・画像を確認する。不足一覧は選択中の猫への適用を集計する。編集画面から開いた場合は条件別の下書き案数・登録案数・差分も表示する。
9. 素材を書き出し、Unityの「Cat Cafe → 素材 → 素材パックを取り込む…」で取り込む。通常のPlayでもこのパックを使用する。「使用中の交流文と対象を確認」でパックID・対応する猫と人物・登録件数を確認できる。

ゲームID未対応は「制作のみ」。その対象の本文は実行用のカタログから除外し、`validation.json` の `interactions.excluded_subjects` と `excluded_entry_count` に記録する。新規登録だけでは猫の加入や客の来店ルールを増やさない。イベント客の共通プロフィール化は今回の範囲外で、実在する客IDへの明示的な対応を使う。

## データと互換性

- 台帳：画像出力先の `interaction_subjects.json`。制作対象ID・ゲームID・画像素材IDを別項目で管理する。新規制作対象IDは自動発行して変更不可。同一種類のゲームIDの二重対応は拒否する。
- 台帳がない場合は従来の3対象を読み込み、旧ローカル設定の資料・旧ミケの画像対応を引き継ぐ。最初の台帳保存までは元ファイルを書き換えない。
- 利用対象外にしても本文は削除しない。既存の候補IDと条件キーは保持する。同名の対象は選択欄でIDを付けて区別する。
- 台帳を使う文章ストアとUnity交流文カタログはversion 2。台帳なしの従来書き出しとversion 1パックの読込にも対応する。CLIは出力先に台帳がある場合にversion 2を使う。
- 既存のミケ専用セリフは変換せずミケ専用として保持する。特定猫の専用文→人物の共通文、それぞれ専用操作→操作共通文の順で選ぶ。未登録の場合は実際の猫名の定型文を使う。
- 差し込みは `{cat}` と `{cat_call}` に限定する。不明な項目と展開後の長さを検証する。Unityでは実行動の確定時に展開して完成本文・候補ID・条件キー・版・画像を保存し、閲覧時に作り直さない。
- 連続生成の実行計画・資料スナップショット・完了結果は生成記録先の `batch-speech.json` / `batch-cat_response.json` に保存する。「前回の続き」で各種類の直近の計画を復元し、未完了だけ再開する。接続先・モデルは再開時にも修正可能。古い資料の計画を使いたくない場合は新しい画面で新規開始する。

Unity検証用には16×16の単色画像1枚と識別用の短い仮文章を使った。画質や本番文章の校正は対象外。客の待ち時間で検証対象が帰らないよう、検証のメモリ上だけ来店間隔を0・25へ調整し、補助の体力成長設定を使わないルールで実行した。ゲームの設定ファイルは変更していない。

通常Playの参照先は、検証前の制作済みパック `75f31c320b3f4de7978ac2c77f7eada1` を保持する。新しい対象の実素材を作って取り込むと、そのパックへ切り替わる。

今回Standaloneビルドは作成していない。共有保存先は従来のLatest 1組を維持し、Pendingや機能別ビルドは追加していない。

容量確認：検証記録は約1.18 MB。`generated` は開始時2,820,683,986 bytes→終了時2,820,697,444 bytes（約13 KB増）。共有Latestは開始・終了とも156ファイル・4,184,220,754 bytesで変化なし。追加ビルド・プロジェクト複製なし。Unity内の検証専用パックは確認後に片付け、元の参照先とProjectVersionを復元した。
