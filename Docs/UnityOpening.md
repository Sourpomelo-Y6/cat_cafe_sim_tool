# 新規ゲーム開始時のオープニング

2026-10-19実装。タイトルの「はじめから」→目標・開始条件と確認→新規ゲームの作成・初期保存成功→オープニング→1日目の営業準備につなぐ。人気・有力者・好感度・自由営業の4目標に対応する。ゲームルール・開始資金・初期猫・費用・乱数・バランスは変更しない。

## 本文と画像

共通本文は `Runtime/Standalone/CafeOpening.cs` の `Lines` が正本。開始時に在店している猫だけを開始データから抽出し、ID・名前を会話の保存情報へ固定する。不在の猫を店にいるようには描かない。主人公の経歴・開業理由・猫の過去など、未設定の世界観は付け加えない。

1. 地の文：「営業前の猫カフェ。まだお客さんのいない店内に、穏やかな時間が流れています。」
2. あなた：「ここで、猫たちとお客さんを迎える毎日が始まるんだね。」
3. 開始時の在店猫ごとに、地の文：「{猫名}がこちらへ顔を向けます。あなたはそっと目線を合わせ、声をかけました。」、あなた：「{猫名}、今日はよろしくね。無理のないように、一緒に過ごしていこう。」
4. 在店猫がいない場合は「あなたは静かな店内を見渡します。今いる猫の様子や予定を確かめながら、準備を進めましょう。」に置き換える。
5. 選択目標に応じて下表の一節だけを変える。
6. 地の文：「まずは1日目の営業準備です。出勤する猫と休む猫を確認し、準備ができたら営業を始めましょう。営業準備では、休業を選ぶこともできます。」
7. 終了案内：「営業準備へ進みましょう。出勤と休養を確認して、営業開始または休業を選べます。」の「会話を終える」で読了を確定する。

| 目標 | 導入の差分（あなた） |
| --- | --- |
| 人気 | 目指すのは、人気のある猫カフェ。毎日の接客を重ねて、お店のことを知ってもらおう。 |
| 有力者 | 目指すのは、有力者とのつながり。お客さんや訪問先との関わりを、少しずつ育てていこう。 |
| 好感度 | 目指すのは、猫との親しい関係。日々のふれあいで、それぞれの猫との時間を大切にしよう。 |
| 自由営業 | 今回は自由営業。決まった目標に縛られず、猫たちの様子を見ながら店を育てていこう。 |

既存 `AcquisitionConversationPanel` を継承する `OpeningPanel` を使用し、話者・文字送り・全文表示・バックログ・保存／読込・設定と、エンディングと同じ本文3行ページ送りを再利用する。猫の節では該当する初期猫の既存通常画像を表示し、未登録なら既存シルエットを使う。背景は既存の店内代替描画 `ConversationRoomGraphic`。新規画像・音声・実行時LLMは使わない。

## 開始・完了・停止

`LocalCafeBackend` の新規作成時に、初期保存へオープニング情報も一緒に記録する。保存成功後に新しいゲームと会話を採用する。作成失敗なら現在のゲームへ会話を付けず、同じrequest_idの再送は既存応答を返して初期化し直さない。既存シーンをそのまま利用し、別の会話システムや初期化処理は作らない。

初回・冒頭から「スキップ」が有効。通常読了とスキップはともに営業準備を開き、営業開始・休業・出勤変更を手動で行える。会話中は日数・tick・自動進行を止め、バックエンドでも保存・ロード・新規開始以外のゲームコマンドを拒否する。加入・費用・報酬・出勤などは演出で変更しない。会話終了だけで営業や自動進行を開始しない。

## 保存と旧セーブ

営業セーブ形式1の任意項目 `opening` を追加する。ゲームルールの状態・リプレイダイジェストとは別に保持する。

| 項目 | 内容 |
| --- | --- |
| conversation_id | `opening.cafe.v1` |
| mode / branch_id | popularity / patron / bond / free |
| cat_ids / cat_names | 開始時の在店猫と表示名の固定値 |
| node / page_offset | 本文の節と、その中の表示ページの開始文字位置 |
| completed | そのゲームで終了したか |
| outcome | 未完了は空、通常読了 viewed、スキップ skipped、デバッグ省略 debug_omitted |
| viewed_branches | viewed のときだけ目標IDを1件、ほかは空 |

途中保存・ロード・別プロセス再起動で同じ節・ページを復元する。文字送り途中の一文字単位の経過時間は保存せず、そのページの冒頭から文字表示を再開する。完了済みは再発動しない。旧セーブの項目欠落・Unityが出力する未設定の空オブジェクトは未設定へ正規化し、会話を推測して追加しない。位置・ID・目標・猫・完了状態・閲覧記録をロード前に検証し、不正なら稼働中のゲームを置き換えない。

## デバッグでの確認方法

通常配布版のタイトルからの新規開始は再生する。EditorであることやDevelopment Buildであることを省略条件にしていない。

- 普段の配布版デバッグ：`CatCafeStandalone.exe --catcafe-debug`。タイトルから新規作成しても `debug_omitted` として営業準備へ進む。
- オープニングを明示再生：`CatCafeStandalone.exe --catcafe-debug --catcafe-opening`。明示再生を優先する。通常起動でも再生する。
- 営業シーンを直接Editor実行：従来どおり既存の初期シミュレーションから営業準備へ進む。新規作成コマンドを経ないので会話を生成しない。
- 既存のプログラム経由の検証入口：`new LocalCafeBackend(...)` はデフォルトで省略する。専用検証は `playOpening:true` を明示して作る。Editorでタイトルから通常の新規作成を試す場合は再生する。
- 保存した未完了会話のロードは、そのゲームの位置を尊重する。起動指定で既存の途中セーブをスキップ済みへ書き換えない。
- 自動検証：`--catcafe-opening-check <絶対検証フォルダ>`。`--opening-restart` はそのフォルダの途中セーブを別プロセスで再検証、`--opening-manual` は検証完了後に専用のオープニング画面を残す。通常セーブは使わず、設定ファイルも検証先の `profile/options-v1.json` に隔離する。

## Extra

営業セーブごとの完了と、端末共通の `extra-v1.json` の解放は分ける。通常読了時だけ既存 `CafeReplayStore` へ本文のスナップショットを登録し、Extraの会話回想へ目標別に4件追加する。途中閲覧・冒頭／途中スキップ・デバッグ省略は解放しない。新規作成や古いスロットのロードで共通解放を減らさず、繰り返し登録しても重複しない。保存・バックアップからの実閲覧記録の取り込みも既存処理を再利用する。

既存の読取専用 `ReplayConversationPanel` で3行ページ送り・バックログ・設定を利用し、回想から営業操作を送らない。既存回想形式に合わせて代表猫の通常画像を1枚持つ。初回に読了した本文・名前を保持し、再閲覧で過去のスナップショットを差し替えない。
