# 休業理由と満杯時のイベント進行（2026-10-18）

## 再現と原因

`Docs/FutureDevelopmentPlan.md` の優先課題と `Docs/UnityDayOff.md`、受け入れ・常連紹介・派遣紹介・結果会話・保存処理を確認した。

修正前の固定LatestのPlayerを起動し、新規開始→営業準備で、1日目・未回答イベントなしにもかかわらず「今日は休業する」が無効で理由が出ないことを実画面で再現した。単独版 `LocalCafeBackend.View()` が `day_off` を設定しておらず、入口と確定の両方が情報なしで拒否されていた。休業コマンド本体は既に実装されていた。

別の停止条件は、依頼を見送った後の未完了の結果会話。既存実装は結果会話を閉じても進行を止め、イベント一覧から再開できるが、一覧では通常の「見送り済み」の記録に分類され、準備・休業画面にはその停止理由が出なかった。回答済みと結果会話未完了を区別できず、回答を終えても休業できないように見える。

満杯を理由に見送りそのものが拒否される不具合は再現しなかった。通常枠6匹、最大拡張後12匹の境界、資金不足でも、既存の見送り処理は加入・支出を伴わず依頼を解消する。結果会話がある場合は会話終了までの制限が別に残る。満杯だけを原因と決めつけて加入判定やゲームルールを変更しない。

## 修正

- 既存の `day_off` コマンドを独立した状態コピーで実行し、休業可否、現在の禁止理由、解消手順、費用・翌日・猫の変化を単独版の状態DTOに接続。IEEE精度情報もコピーし、予測で本体・乱数・保存・日程を変えない。セーブ用のRestoreは呼ばず、コマンドに存在する正当な制限をそのまま評価する。
- 準備画面の入口は休業不可でも開ける。準備画面と休業画面の両方に、会話の現在状態とルール上の制限を表示。確定ボタンを無効にしても説明を読める。未確定の休養案の確定・取消という従来の制限は維持する。
- 依頼／常連紹介の結果会話は「見送り済み／受け入れ済み・結果会話が未完了」と表示。両方未完了なら両方を表示し、イベント一覧の「回答・会話待ち」から「会話を終える」まで読む手順を示す。
- 休業画面に「イベント一覧で確認」／交流中の「交流へ戻る」を追加。イベント一覧は回答待ちと結果会話待ちを同じ優先分類に集め、結果会話には「回答済み・結果会話の続き」と明記。完了時は件数・分類・理由を即更新する。
- 満杯時の「迎える」の現在数／上限・禁止理由、「見送る」、閉じた結果会話の再開、会話終了、保存再開、回答冪等性は既存実装を再利用。費用・加入・イベント回答・会話ID・保存形式・バランスは変更しない。
- 予約当日、交流途中、他の回答待ち、営業段階、経営終了、おまかせ中の制限を維持する。会話完了は別イベントの制限を解除しない。
