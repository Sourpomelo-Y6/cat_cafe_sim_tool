# 日常交流の文章編集・保存（第1段階）

2026-10-15実装。[ローカルLLMによる制作案](LocalLlmInteractionTextPlan.md)のうち、条件別の手入力・下書き・確認登録に対応した。LLM生成、画像付き組み合わせプレビュー、Unity向け書き出しとゲーム内候補選択は後続。

同日追補：[ローカルLLMで3案を生成・選択取り込みする第2段階](InteractionLlmGeneration.md)を追加した。以下は第1段階の仕様・検証記録。現在の画面では生成ボタンも利用できる。

## 使い方

1. `python run.py` で制作ツールを起動し、「日常交流の文章を編集…」を押す。
2. 「人物のセリフ」または「猫の反応」を選ぶ。人物はプレイヤー／佐藤さん、猫はミケが初期対象。交流相手の猫はミケに固定している。
3. ねこじゃらし／なでる／休憩、操作・強さ、猫の反応条件を選ぶ。人物のセリフには猫の反応条件を付けない。猫は通常・好意的・熱心・拒否・戸惑い・低体力を区別する。休憩は通常／低体力に限定する。
4. 案1〜3を入力する。人物は発話本文だけ、猫は反応描写だけを入力する。各200文字まで。空欄は未制作として残せる。重複した文章は保存できない。
5. 「下書きを保存」で制作途中を保存する。「保存内容を再読込」で、同じ条件の下書きを優先し、なければ登録済み素材を読む。
6. 「登録内容を確認」で対象・条件・画像キー・3案を確認し、「確認した文章を登録」を押す。登録には少なくとも1案が必要。確認後に編集・条件変更した場合は再確認が必要。

登録は制作素材の保存を意味する。現在のUnity書き出しやゲームの文章表示にはまだ接続していない。既存の紹介文・4場面の編集とローカルLLM機能はそのまま利用できる。

## データと保護

- 下書き：制作ツール内の `user_data/interaction_text_drafts.json`。
- 登録済み素材：画像出力先の `interaction_texts.json`。標準では `../cat_cafe_sim/saves/content_images/interaction_texts.json`。`run.py --output` を指定した場合はその出力先へ保存する。
- 既存の `text_drafts.json`／`texts.json`、画像、ゲームのセーブには書き込まない。
- 版1のJSONに `entries` 配列を持ち、文章種別・対象ID・行動・操作・反応・画像キーを条件として保存する。人物IDは `player`／`guest-1`、猫IDは `cat-mike`。この段階では任意の人物追加・口調プロフィールの編集や制作素材IDとの画像照合は行わない。
- 操作は既存の `MODE_ACTIONS` から許可された通常操作を使う。なでるで「激しく動かす」は選べない。操作共通なら行動の基準画像キー、個別操作なら `teaser__adapt` などの組み合わせキーを表示する。休憩は全動作共通の `pause` キーとして記録する。
- 各条件に固定の3スロットを持ち、空欄を含めて順序と候補IDを維持する。IDは条件とスロットから作り、本文の修正では変えない。将来のUnity用カタログは別工程で、現在のファイルをゲームが直接読むわけではない。
- 登録時は同じ条件の下書きも同期し、次回起動時に古い下書きが採用文を覆わないようにする。他の条件は変更しない。
- 未保存で条件を切り替える・再読込する・閉じる場合は、「下書きを保存／変更を破棄／編集を続ける」を選べる。制作ツールの親画面を閉じる場合も同じ保護を行う。
- ファイルの形式、候補ID・順序・文字数、条件の重複を検証し、不正な既存ファイルは上書きしない。保存は一時ファイルを書いて置き換え、失敗時は一時ファイルを片付ける。読込後に同じ条件が別の編集で更新されていた場合は保存を拒否し、再読込を案内する。

人物のセリフと猫の反応は別の素材であり、全ての組み合わせを人物ごとに複製しない。数値から猫の反応を決定する処理や、文章の無作為選択は今回追加していない。
