# Windows版に収録された画像の重複

対象は2026年11月16日 08:52 JSTに生成された `Latest` のWindows版です。既存の `LastBuild.buildreport` と実行版を読み取りました。

| 項目 | 結果 |
| --- | ---: |
| Windows実行版全体 | 7,034,037,622 バイト（7.03 GB） |
| `resources.assets.resS` 全体 | 6,929,533,584 バイト（6.93 GB） |
| 現行パックの画像本体860枚 | 901,775,360 バイト（0.90 GB） |
| 旧パックの画像本体860枚 | 901,775,360 バイト（0.90 GB） |
| 現行・旧の2パック間で、別の位置にある同一データ | 860組・901,775,360 バイト（0.90 GB） |
| 同じ860画像の全パックでの収録数 | 4,961個 |
| 同じ860画像の全収録データ | 5,201,985,536 バイト（5.20 GB） |
| 同じ860画像を各1個と数えた場合の差 | 4,300,210,176 バイト（4.30 GB） |

現行パックは `ad3e7e84e8c7491fb8aad895e243de4e`、旧パックは `cbe0df94e7a5401a8f466406c105b493` です。旧パックのリソースパスは確認済みの旧セーブ2件に残っています。

## 計測方法

ビルドレポートの元素材パスとオブジェクトの位置を `resources.assets` の画像名と照合しました。各 Texture2D のストリーム情報をレポートの `resources.assets.resS` の記録にも照合し、画像本体の位置・サイズが一致することを確認しました。画像本体の実バイトを SHA-256 で照合しました。

集計値には画像本体を含めています。Texture2Dのメタデータ、書き換え後の参照テーブル、ファイルのアラインメント、再ビルド後の差は含めていません。画像の共用は容量面で検討する価値があり、旧セーブが保存しているリソースパスから同じ画像を取得できることを条件とします。

同じ860画像の別領域への収録数は画像によって2〜17個です。画像と格納位置の対応は `texture-streams.tsv` にあります。
