# 店からの家出・帰還のADV接続

2026-10-21。Unity単独版の経営ルールによる家出を対象とする。山あいの宿の派遣トラブルは既存の別処理を維持する。

## 現行実装と旧資料の違い

`Docs/UnityMissingCats.md` のPython Session・HTTP・再接続・猫ID単位の記述は当時の連携版の記録。標準起動は `LocalCafeBackend` とC#の `CafeSimulation` を使用する。今回の単独版では案件IDを `choice` に渡し、猫IDとの一致を検証して帰還を確定する。HTTP明示起動の旧UI・通信は従来どおり。

家出条件、子猫の抽選、帰還までの閉店回数、費用、人気低下、帰還時の体力・ストレス・体調・疲労・出勤設定は変更しない。従来から帰還回復は `Simulation.MaxStamina(cat.id)` を使用していた。表示側の共通最大値参照を猫別最大値に揃えた。子猫は在籍猫として生成しない。既存の基準画像と共通代替表示のみ使用する。

## 状態と操作

| 状態 | 会話・進行 |
| --- | --- |
| 発生通知 | 家出した事実と、今回から記録できる接客後ストレス基準だけを説明。閉じても進行可能 |
| 家出中 | 残り閉店回数は記録一覧。任意の短い状況確認。営業・休業で日程を進め、日数減少ごとの会話割込みは行わない |
| 帰還待ち | 子猫・費用が既存処理で公開される段階。短い会話を閉じ、記録一覧の費用・確認後資金・経営終了の警告を読んで「帰還と費用を確認する」。会話の閲覧だけでは精算しない |
| 帰還確定 | 確定した子猫・費用・精算直後の残金・回復体力・ストレスを表示。体調・疲労を引き継ぎ、休養予定であることと猫一覧での出勤確認を案内 |

確認前の帰還待ちは既存ルールが日程進行を制限する。確認後の未読結果も営業・休業・目標継続を止め、イベント一覧の「猫の家出・帰還」から対象案件を再開して最後まで読む手順を表示する。成長表示と結末は未読帰還結果に重ねない。費用による経営終了では帰還結果を読んだ後に既存の結末へ戻る。開いている他会話と共通UIが重なる場合は共通会話の開閉制御に従い、家出会話は一覧から再開できる。

共通 `AcquisitionConversationPanel` の最大3行ページ送り、文字速度、全文表示、次へ、バックログ、保存・読込、オプションを使用する。会話を閉じると案件の記録一覧を開く。読了後は営業準備などの既存画面へ復帰し、猫の状態と出勤設定を確認できる。帰還待ちでも単独版の画面は閉じられ、進行不能理由から一覧へ戻れる。

## 本文

`CafeMissingDialogue.Lines` が本文の正本。名前・数値は対象案件の確定情報を差し込む。

- 通知：「{猫名}が店から家出した。」「接客後のストレスが家出の基準に達した記録があります。今は帰還を待ちましょう。」「家出中は接客・交流・派遣に参加できない。営業か休業で日程を進められる。居場所や帰還結果は、まだ確認できていない。」
- 旧家出の原因不明：「家出日や原因の記録はありません。今分かる状態を確認しましょう。」
- 待機：「{猫名}は、まだ家出中です。帰還までの残り閉店回数は記録一覧で確認できます。」「この状況確認は任意。会話を閉じて営業や休業を進めよう。出勤できる猫がいなくても、営業準備の休業を利用できる。」
- 帰還待ち：「{猫名}が帰還待ちになった。」「子猫の有無と費用は、帰還の記録に公開されています。一覧で内容と確認後の資金を確かめてから、帰還を確定しましょう。」「この会話だけでは帰還・費用は確定しない。会話を閉じると記録一覧へ戻る。帰還を確定するまで営業・休業は進められない。」
- 確定：「{猫名}の帰還が確定し、店に戻った。」子猫あり：「子猫の引き渡し費用は {費用}。子猫は在籍猫に追加されません。」子猫なし：「子猫の引き渡しはありません。費用は0です。」最後に「精算直後の資金：{残金}。帰還時の体力：{体力}、ストレス：{ストレス}。体調・疲労は引き継ぎ、休養予定。猫一覧で状態と出勤設定を確認しよう。」

事故・負傷・居場所・捜索の成功など、記録にない物語は追加しない。帰還前の子猫や費用は本文・バックログ・Extraへ出さない。

## 保存・互換・Extra

`CafeSnapshot.missing_cases` に案件ID、猫ID、記録できた家出日・原因、帰還確定日、精算時の数値、4段階の会話進行を保存する。新規案件は `missing-{日}-{猫ID}`。旧家出中／帰還待ちは初回観測時に `legacy-missing-{観測日}-{猫ID}` を割り当てるが、家出日は0、原因は未記録のままとする。同じ猫の次の案件・複数猫の案件を別々に保持する。選択案件と段階はセーブの表示メタデータに保存する。

旧セーブで既に帰還して記録がない猫について過去の案件・原因・会話・既読は作らない。旧家出中は現在の状態説明から、旧帰還待ちは確認から始められる。新フィールド未収録の数値精度記録には追加枠がないため従来どおり読める。新しい案件の数値は既存の倍精度保存機構を通る。ゲーム操作リプレイのハッシュから表示用の案件記録を除外し、既存リプレイの互換性を維持する。

帰還確定は従来の `resolve_missing` で一度だけ行い、同じ案件の再確定・別猫・古い案件を拒否する。既存のrequest ID・revision・ロード時のepochも利用する。会話の完了や再表示は精算・回復・日程を再実行しない。

読了した通知、任意待機、帰還待ち、帰還結果（子猫あり／なし）の5分岐をExtraへ登録する。未読や途中で閉じただけの分岐は解放しない。Extraは既存の固定本文回想パネルだけを使い、営業状態へ操作しない。各分岐の初回読了を代表として保存し、過去の全案件を並べる機能ではない。

## 検証

最終結果・容量は作業完了時に追記する。検証は専用セーブと記録を `Logs/MissingConversation` に分離。通常のルールJSON・素材・通常セーブは変更しない。検証用の初期資金・イベント日・子猫確率などをメモリ上で短期化し、自然発生の記録も別に確認する。

入口は `CatCafePreview.Editor.MissingConversationVerification.VerifyAndBuild`。指定の `build_standalone.ps1 -ProjectPath C:/Users/hi-wa/unity_workspase/CatCafeSim -ExecuteMethod ...` で共通 `StandaloneBuildStorage` の固定Latestへビルドする。Playerは `--catcafe-missing-adv-check <専用出力フォルダ>`、別プロセス再開は同じフォルダと `--missing-resume` を使う。

## 残る課題

標準条件での長期バランス評価、全猫・全解像度・全イベントの同日組み合わせの網羅は後続。旧セーブにない原因・過去の会話は今後も補完しない。Extraは分岐の代表記録であり案件台帳ではない。今回の実画面確認で使う開始状態は専用fixtureであり、通常開始から全事象を自然発生させた手動通しとは区別する。
