# 日常交流文の画像付きプレビューとUnity向け書き出し

2026-10-15実装。第3段階として、登録済みの人物のセリフ・ミケの反応を、行動文・地の文・対応画像と組み合わせて確認できるようにした。採用済み交流文の別添カタログも既存の素材パックへ書き出す。Unity側のカタログ取り込み・ゲーム内の文章選択は次の段階であり、今回はゲーム処理を変更していない。

## 使い方

1. 制作ツールの「日常交流の文章を編集…」で文章を制作する。
2. 「画像付きで組み合わせを確認…」を押す。人の話者、行動、操作、猫の反応条件を選び、人と猫それぞれの候補を案1〜3から切り替える。
3. 「編集中の案を一時的に重ねる」がONなら、開いた時点の編集内容をその条件に重ねて表示する。「編集中・未登録」と明示し、保存は行わない。OFFにすると登録済み素材だけを確認できる。本文を編集した後はプレビューを開き直す。
4. 表示画像と文章の動作・状態を確認する。行動文・地の文は試作用の共通文で、実際のゲーム結果や体力増減を再現しているわけではない。
5. 「未制作の条件」タブで、登録済み素材だけの対応状況を確認する。プレビューで読めても未登録の案は対応済みに数えない。
6. 画像制作画面の「Unity向けに書き出す…」から保存先を選ぶ。結果画面に交流文の案数・不足条件も表示する。

同じプレビューを何度表示しても、文章の保存や抽選は行わない。候補は手動で選ぶ。人の発話、実行する動作の説明、猫の描写、地の文を分けて並べる。未制作の文章はその場で創作せず「未制作」と表示する。専用操作の文章を優先し、なければ同じ人物／猫・行動・反応の操作共通文を使う。通常・好反応の文章を拒否・低体力へ代用しない。

## 画像とIDの対応

ゲーム側の `cat-mike` と制作画像側の `playtest-mike` は、既存のUnity表示定義と同じ明示的な初期対応を使う。現在の猫一覧に `playtest-mike` がない場合、名前が「ミケ」でも推測して結び付けない。

独自の制作IDを使っている場合は、プレビュー上部の制作画像IDから該当する猫を選ぶ。一時選択のままなら表示にだけ使う。「画像ID対応を保存」を押すと、画像出力先の `interaction_image_bindings.json` に保存し、以後の書き出しにも使う。これは画像IDの対応だけを変更し、文章やゲームセーブは変更しない。不正な対応ファイルは書き出しを停止する。プレビューから明示的に正しいIDを選んで修正できる。

画像は、操作別画像→同じ行動の基準画像→従来の遊び画像（ねこじゃらしのみ）→通常画像の順に探す。休憩は `pause`→`normal` とし、休憩だから眠っているとは限らないため `sleep` を自動代用しない。要求キーと実際に表示したキーを明示し、代替・未登録・読み込み失敗も表示する。登録があっても不正なPNGヘッダーや欠落ファイルなら次の候補へ進む。Tkで画像を開けない場合もエラーを示して以前の画像を残さない。

現行の画像キーは操作別であり、拒否・低体力などの反応まで保証していない。プレビューは絵と文章を目視で照合するための画面で、意味の一致を自動判定・承認する機能ではない。該当画像が不足する場合は別途制作する。

## 書き出しファイル

既存の `bundle.json` の版1、画像、紹介文の書き出しを維持し、同じ素材パックに以下を追加した。

| ファイル／項目 | 内容 |
| --- | --- |
| `interaction_texts.json` | 版1、パックID、内容から求めたrevision、猫と制作画像IDの対応、人物名、採用済み条件と非空の候補、画像対応、共通の行動文・地の文 |
| `validation.json` の `interactions` | 登録条件数・候補数、専用文／操作共通文を使った対応数、不足条件の配列、画像に関する注意 |

カタログの `entries` は、文章種別・対象ID・行動・操作・反応・画像キーを持つレコードの配列。各レコードの `variants` は候補ID・スロット番号・本文の配列で、空欄を除外する。案2だけが登録されていれば、そのIDとスロット2を維持して出力する。任意IDをキーにした辞書を避け、将来C#のDTOとJsonUtilityで扱える配列形式にした。今回実Unityでのカタログ読込検証は行っていない。

`revision` は採用済み本文・条件・画像の対応・共通文から計算したSHA-256。同じ内容なら出力先やパックIDが変わっても同じ版になり、本文や画像が変われば変わる。`pack_id` は従来の素材パックと一致させる。画像は既存のパック内 `images/<SHA-256>.png` を参照し、同一画像を重複保存しない。下書き、編集中の案、未採用のLLM生成記録は読み込まない。登録済み素材が壊れていれば新規出力を作らず、書き出し中の失敗では今回作ったパックだけを片付けて既存パックを保持する。

不足条件の対象は、プレイヤー・佐藤さんのセリフ、ミケの反応、ねこじゃらし・なでる・全動作共通の休憩を組み合わせた制作上の52条件。1案以上あれば対応済みとする。全3案が揃ったことを意味しない。拒否など標準のミケでは発生しない条件も含む制作上の確認表であり、ゲーム内で全条件が発生可能だという評価ではない。切り替え・特別行動・他の猫などはこの確認表の範囲外。

休憩は制作データでは `mode=pause, action=pause` に正規化している。ゲームでは他の動作中にもpause操作があるため、次のUnity接続段階でこの共通条件への変換を行う必要がある。

現行のUnity素材取り込みは従来の `bundle.json` を読む。今回追加した別添カタログのUnityへの取り込み・保存と、ゲーム内で実際の行動結果から候補を選ぶ接続は次の作業。今回書き出しただけでゲームの表示文は変わらない。

## 検証

専用14テスト（データ9、実Tk画面5）が成功した。

- 専用操作と操作共通文の優先順位、反応・人物の分離、未登録の一時表示。
- 採用済み候補だけの出力、空欄除外と候補ID・スロット維持、画像の重複防止、パックIDの一致。
- 同じ内容のrevision維持、本文変更での版更新、以前のパックの不変。
- 制作対象52条件の集計、専用・共通文を含む不足の検出、全対象を登録した場合の不足解消。
- 名前から画像IDを推測しないこと、明示的な対応保存、画像の欠落・破損・代替表示、休憩で睡眠画像を自動使用しないこと。
- 壊れた素材・対応の書き出し拒否、下書きストア指定の拒否、出力失敗時の新規パックだけの削除。
- 画像付き実Tk画面での候補切り替え、閲覧を繰り返しても本文・画像対応表が変わらないこと、再読込エラー時の表示保持、840×680での画像と本文の配置。
- 制作ツールの実ボタンから素材パックを書き出し、交流文と不足条件が含まれること。

既存の関連44テスト（素材書き出し6、交流文編集17、交流文LLM10、画像制作ツール8、外見プロフィール3）も成功した。画面の配置はTkの実ウィジェット寸法で確認したもので、スクリーンショットの目視確認や長時間の手動操作を実施した意味ではない。画像のテストは既存の検証画像を使い、反応別の新しい画像は制作していない。

再現は制作ツールのフォルダで行う。

```powershell
$env:CAT_CAFE_TEST_GUI='1'
$env:PYTHONUTF8='1'
python -m unittest discover -s tests -p test_interaction_preview.py -v
python -m unittest discover -s tests -p test_unity_export.py -v
```

CLIの素材書き出しも同じ交流文出力を使う。

```powershell
python unity_export.py --source <登録素材のフォルダ> --destination <素材パックの保存先>
```

制限環境の検証では `TEMP`／`TMP` にワークスペース内 `Logs/InteractionPreview/temp` を指定した。書き出しテストの素材パックはテスト終了時に片付け、ゲーム用素材・セーブを変更していない。Unityの検証ビルド、プロジェクトコピー、Library追加は行っていない。
