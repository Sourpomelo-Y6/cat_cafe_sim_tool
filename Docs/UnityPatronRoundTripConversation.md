# 有力者3人の派遣往復ADV（2026-10-23）

## 仕様・本文

地域の有力者、気分が変わる有力者、条件に厳格な有力者を、通常派遣の `CafeDispatchDialogue` / `DispatchConversationPanel` / `AcquisitionConversationPanel` へ接続した。既存の有力者パネルで猫と行き先を選び、「出発内容を確認」から相談する。表示構造・最大3行ページ送り・文字速度・全文表示・次へ・バックログ・保存・オプションは共通機能を使う。

本文の正本は `Runtime/Standalone/CafeDispatchConversation.cs` の有力者分岐。既存の通常派遣本文を共通構造として使用し、訪問先を3人の既存呼称に差し替える。個人名、私生活、過去の関係、派遣先で起きた未確定の出来事は追加しない。既存の猫画像／代替シルエットと店内背景を使い、新規画像・音声・実行時LLMは追加しない。

- 出発前4節：訪問相談、希望と日程の確認、対象猫の確認、希望に合わなくても既存の出発条件に従う説明。選択付近で実際の条件・不可理由・閉店回数・報酬・加点見込みを表示する。
- 出発／取消後：既存の出発結果3節／取消結果2節。取消では費用・日程を変更せず、同日再相談できる。
- 派遣中3節：任意の状況閲覧。希望・一致・報酬・加点は出発時固定で、現在の希望が変わっても再判定しないこと、営業の閉店・休業で日程を進められることを説明する。
- 帰還前3節：出発記録、受取確認、固定条件・報酬・加点の確認。帰還しただけでは反映しない。「あとで確認する」は受取を実行しない。
- 受領結果3節：訪問のお礼、猫の様子と次の予定、報酬・派遣経験の受取済みと満足度上限の説明。共通の中立的な結果に確定条件・一致／不一致・報酬・固定加点を付ける。不一致や上限で増えない場合を成功・希望達成とは描写しない。

`CafeSimulation.PatronPreview` が既存のDispatchTerms/PatronTermsを投影し、既存のPatronEventGainを投影とExtraからも参照可能にした。画面に報酬・加点式を追加していない。出発は `dispatch_patron`、受領は `receive_patron` から既存の派遣・帰還処理へ委譲する。希望、期間、疲労上限、担当可能猫数、同時・同日制限、報酬、満足度、乱数、rules_id、バランスを変更しない。不一致を独自の出発禁止条件にしない。

## 保存・再開・順序

既存の任意表示項目 `dispatch_conversations` を共用し、日付・猫・行き先で案件を分ける。取消後の再相談では読了取消を維持し、後日の再派遣は別案件とする。3人への並行派遣と通常派遣も同じ保存検証を通す。node/page_offset、出発・派遣中・帰還の各進行を既存の原子的保存で復元する。

会話を閉じても、未確定の出発相談と派遣中の閲覧は新たな日程制限を残さない。派遣中説明を強制閲覧にしない。帰還確認待ちは既存の帰還制限、確定結果の未読は共通の結果会話制限が残る。イベント一覧の「有力者への派遣・帰還」から再開し、結果を「会話を終える」まで進める。営業・おまかせは自動再開しない。

最終受領時も、まず既存処理で一度だけ報酬・満足度・固定達成記録を反映し、帰還結果の後に既存有力者エンディングを表示する。成長候補・他目標・別会話の既存優先順を維持する。結果会話が残る間のcontinue/advance系コマンドも拒否し、UIを閉じても結果を飛ばさない。既存request_id再送とrevision、受領済み拒否を維持する。

| 旧セーブの状態 | 対応 |
| --- | --- |
| 派遣中、会話配列なし | 任意閲覧を開いた時点の派遣中から。過去の出発会話・読了は作らない |
| 帰還待ち、会話配列なし | 帰還確認から。未受領を維持 |
| 受領済み、会話配列なし | 既存記録表示。過去の結果会話とExtra解放を補わない |
| 達成未確認／継続済み | 既存有力者エンディングの互換方針を維持。既に継続した営業を止め直さない |
| 会話途中／読了済み | 実在する進行だけを保存・復元する |

対象は現行ローダーが受理する営業形式とrules_idの旧保存。異なるルールのセーブ移行は追加しない。

## Extra

3人それぞれ `dispatch.patron_visit.v1` / `dispatch.patron_moody_visit.v1` / `dispatch.patron_strict_visit.v1` を使用。末尾の `.departure` はdeparted/cancelled、`.travelling` はtravelling、`.return` はreceived。共通の受領分岐は確定事実を記録し、一致・不一致どちらにも成立する本文を用いる。読了した12単位だけを追加し、未読の分岐・過去の会話は補わない。既存通常派遣と `ending.patron.v1` のID・解放は維持する。

回想は既存の保存済み本文を読み取り専用で再生する。営業セーブの読込やコマンド送信をせず、報酬・満足度・現在の希望・日程・継続処理を変更しない。帰還回想には保存された出発条件・一致・報酬・加点を含める。
