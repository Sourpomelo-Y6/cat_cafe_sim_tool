# 行動・反応の表示名編集

2026-10-29。ユーザーが、行動追加は保留のまま軽い名前変更だけを進める方針を採用。内部IDを維持した表示名の上書きを実装した。新行動・反応条件の追加、効果・成長・数値の変更は含めない。

## 操作

1. 素材制作Toolの「対象管理」→「行動・反応の表示名…」を開く。
2. 行動の種類（8種類＋休憩）、操作・強さ、通常反応と特別場面の名前を入力する。内部IDと標準名は読み取り専用。空欄は標準表示。
3. 保存後、Toolを再起動する。対象選択・文章編集・画像場面・プレビューの表示へ反映される。既に開いている編集中の画面を強制的に切り替えないため、同一セッション中の即時反映はしない。
4. Unityへ反映する場合は、Tool再起動後に既存の「全素材書き出し」を実行し、Unityで取り込み・再ビルドする。ビルド後の外部パック更新機能ではない。人物画像だけの単独書き出しには含めない。

設定はToolのuser_data/display_labels.json。リポジトリのuser_data除外方針に従うローカル設定。Toolの再起動後も保持する。全欄を標準へ戻す操作も、保存するまでは適用しない。32文字以内・同一分類内の重複禁止、改行／制御文字／<>禁止。画像場面の標準名と衝突する行動名も拒否する。保存は検証後に原子的に置換し、入力不正時は既存ファイルを保持する。不正な設定ファイルは画面から無断上書きせずエラーを表示し、Tool表示は警告付きで標準へ戻す。

## データと互換性

bundle.jsonの任意項目display_labelsにversion=1とmodes/actions/reactionsのID・label配列を追加。変更分だけを格納する。既存の正式パック書き出し・ContentPreviewSetup.Import経路を利用し、ContentValidationで受入時検証。旧パックの項目欠落は許容し、以前の文脈別の標準名へフォールバックする。

Unityは行動種類・操作・通常反応の表示入口、席の行動／反応表示、特別場面の反応表示、猫詳細の好み表示で上書きを使用する。特殊反応の表示名を変えても、Toolの通常反応6条件は増えない。内部mode/action/reaction/scene_key、本文候補ID、画像キー、セーブ形式を変更しない。既存採用本文や保存済み履歴の文章を自動置換しない。ルール説明・固定の案内文・生成用の英語画像プロンプトも一括置換しないため、新しい呼称に合わせた文章校正・画像確認は別作業。

## 確認

一時設定で「声をかける→おしゃべり」「戸惑い→きょとん」、操作と特別反応の変更を確認。新規6テストで保存・標準復帰・不正値拒否と既存ファイル保持、Tool再起動相当のモジュール再読込、ID／条件キー不変、素材書き出し時の設定同梱・元本文保持、Tk設定画面を検証。

既存の制作ワークフロー4、書き出し6、文章編集17、全行動4、LLM10テストが成功。Tkはsandbox内のTcl初期化が失敗したため通常環境で一時データのみを使って再実行。UnityはDisplayLabelVerification.VerifyでPythonから出力したJSONの読込、行動／操作／反応表示入口、特別反応、未変更の標準名、旧パックの欠落項目、不正version／ID／markup拒否、メモリfixture復元を確認。検証証跡はLogs/DisplayLabels。

実設定・採用データ・有効パック・シーン・Latestは更新せず、Unityソースを同期した。ビルド・新しい素材制作は実施していない。ゲームへの実使用は設定してパックを取り込み再ビルドした後になる。全表示箇所の実手入力・配布版の表示は今回未検証。

Unity依存を読込アダプターへ分離し、既存StandaloneChecksの.NETビルドも成功。--display-labelsによる7検査で行動・操作・通常／特別反応の上書き、未変更名、内部ID維持、表示設定復元を確認した。

## 旧素材パックの互換修正（2026-10-30）

Unity JsonUtilityは、旧パックにdisplay_labelsが存在しない場合でもversion=0の空オブジェクトを生成する。これを未設定として扱い、標準名を使用するよう修正した。従来のnullのみの検証では素材パック全体が読み込み失敗し、全画像が表示されなくなっていた。

実際のResources内の旧パックをUnityでデシリアライズし、全体検証と画像988参照のTexture2D読み込みに成功。表示名の変更・不正値拒否の既存検証も成功（Logs/DisplayLabels/legacy-fix.log）。素材・セーブ・ビルドは変更なし。

## イベント一覧ボタンの表示競合修正（2026-10-30）

PythonBusinessHeader.AlignCommandsが毎回文字サイズ14・自動縮小ONに戻し、PythonEventListPanelが未確認0件時に17・自動縮小OFFを設定していた。イベント一覧の文字サイズ管理をイベント側に統一し、ヘッダー側は位置・余白のみ更新する。Unity実シーンで0・1・12・0件それぞれ120回のヘッダー更新後も文字設定が保持されることを検証済み（Logs/DisplayLabels/event-header-fix.log）。シーン保存・ビルド・セーブ更新なし。
