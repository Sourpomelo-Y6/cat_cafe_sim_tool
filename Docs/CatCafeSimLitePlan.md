| ---: | --- |

常連は既存の客が変化する仕組みとして残す。通常6人の来店時刻と曜日は維持し、人気追加を現状の4＋2から1＋1へ変更する。席拡張による追加客5枠、静かな交流・遊び・触れ合いの専門客3人、祭りの日付付き追加客は初回の来店対象から外す。席増設と接客設備は残す。`CafeCustomers` は通常客と人気客を連番で組み立て、席拡張と祭りで別 ID を追加するため、来店生成、顧客一覧、会話、履歴と保存の検証をそろえて更新する。`guest-8` は第2段階に移る。予約・長毛客が重なった日もソラ1匹で処理可能な日程とし、両立できない場合は予約を見送れることを確認する。

**残す遊び**は、出勤・準備 → 待機と席割当 → 手動／自動接客と猫の交流 → 閉店・収支・人気 → 休養・育成 → 翌日の営業。既存の遊び・なでる・ブラッシング・声かけ等の行動、猫の切り替えと複数カード表示、客の常連化・信頼回復、用品・設備、近隣への派遣、ミケの任意イベントと収録対象の回想、保存・再開を含める。経営・人気・絆の開始目標を残し、有力者目標は初回見送りとする。現行の有力者条件には黒・白・長毛の分岐があり、3匹構成で条件の再設計が必要になる。来店減で収支や人気の伸びが変わるため、通常の資金と期限で人気の最終段階・VIP・結果・継続営業に到達できるよう調整する。経営と絆も新規開始から結果まで通す。

## 参照を解決して素材を選ぶ

組み立てに使う入力を [収録ファイル一覧](CatCafeSimLiteInventory.json) に記録した。基準コミットに追跡されている1,373ファイル、212,568,445バイト。各ファイルにパス、サイズ、SHA-256、用途を記録した。画像は猫90枚、客12枚、イベントの共用画像2枚。イベント15件それぞれの通常立ち絵と専用画像も記録した。

- `filter-json` の5ファイルは軽量版用に書き出す。交流文は標準3匹と来店12枠に加えて `player` の定義を保持する。現行データの ID で絞ると画像対応96行、交流文366件（猫反応250件、人物発言116件）。共通行動文・地の文を保持し、書き出し時に `revision` を再計算する。肖像の絞り込みと、営業ルール・表示定義の変更は同じ ID 一覧に合わせる。
- `guidReplacements` の5件は、営業シーンの収録外4画像を猫シルエットへ、プレビュープレハブの旧取り込み画像1枚を現行のミケの通常画像へ差し替える案。対象は `Texture2D` の参照12箇所。シーンとプレハブ上で表示を確認する。 `guidsToResolveInUnity` の44件は Unity の組み込み・パッケージ参照を含むため、インポート後に解決を確認する。
- `editor-review`、`test-review`、`legacy-review` は依存確認用の候補。公開用ツリーに必要な検証・生成入口を確定してから整理する。入力一覧の容量はこれらを含み、生成後の JSON や公開用文書の容量は組み立て後に測る。

1. `StandaloneScreenSetup.Build` が使う `CatCafeTitle.unity` と `CatCafePythonState.unity` を入口にする。後者は名前に Python を含むが、共有版では Unity 内の `LocalCafeBackend` で動かす。シーン、プレハブ、マテリアル、フォント、設定の依存を `AssetDatabase.GetDependencies` と YAML の GUID／`.meta` で照合する。営業シーンには現行取り込み画像への直接参照が7件あり、共有画像を含む。さらにシーンから参照される `ContentPreview.prefab` は旧取り込み `bba09…` の画像を1件参照する。収録素材へ差し替えるか必要な機能と一緒に外し、削除対象パスへの GUID 参照を解消する。単独の検証用 `CatCafeStandalone.unity` は共有版の通常起動入口から外す。
2. 文字列によるロードを追う。`CatCafeContent/catalog` → `bundleResource`／`interactionResource` → 猫 ID・交流文・画像キー、`human_portraits` → `pack_id`／`game_id` → 肖像、`CatCafeEvents/catalog` → 任意イベント定義 → 通常画像、`CatCafeStandalone` → ルール・表示・成長・フォールバック。`rules.json`、`presentation.json`、猫の表示名・画像結び付け、交流文の話者／対象猫、ギャラリー・回想のキーも同じ収録表に合わせる。カタログの版・ハッシュは既存の生成・検証規則に従う。過去のカタログを固定パスで読む `NarrativeProofreadingSmoke` などは共有用の検証入口から切り離すか軽量版のデータで動かす。
3. 公開許諾が確認できた実行用素材の許可リストを作り、ID・参照元・相対パス・GUID・サイズ・権利根拠を記録する。タイトル背景、M PLUS フォントとライセンス、汎用猫シルエット・客アイコン、ミケの導入画像、必要な共通 UI を含める。未収録シーンや素材からの参照が残る場合は収録前に解決し、必要な `.meta` は保持する。

## 容量の目安

猫3匹の参照 PNG は重複を除いて **90枚、171.0 MB**。来店12枠の現行肖像は **15.9 MB**。初回調査時の `Assets/Resources` 外の `Assets` 全量約24.2 MBを共通分として仮置きし、個別イベント分約4.9 MBを加えると、**3匹 約216 MB、4匹 約275 MB、5匹 約335 MB**。3匹案は初回調査時の `Assets` 比で約97.6%減の見込み。対象素材が決まったら共有素材の重複や追加参照を織り込み、実ファイル容量・Git pack／clone 容量・Unity インポート後の `Library`・Windows Player サイズをそれぞれ測る。現時点ではいずれも試作・ビルド前の見積もり。

初回の目安は追跡ファイル合計 **250 MB**、増員時の上限案は **300 MB**。4匹目は全ファイルを計測して300 MB以内で、加入と保存まで通れば採用候補。5匹目は実行用画像の縮小や共通化を試し、300 MB以内で日本語 UI・拡大表示の見た目と加入後の回帰確認を通った場合に採用する。全画像の単純な解像度変更は先行させず、重複パックと未使用画像の除外から進める。

## 開発者向け追加パック

初回試作は、3匹版ならナナ、ナナ収録ならマロン。猫単位の画像・`.meta`・台詞・定義を固有パスに置き、必要な場合のみその猫のプレハブ・アニメーションを含める。調査した現行構成の中心は PNG と JSON。共有のシーン・ルール・カタログや既存 GUID をパックのインポートで上書きしないよう、追加データを検証してカタログと加入設定を生成する Editor 手順を設ける。パックの前提バージョン、猫 ID、適用・無効化手順、保存への影響、ライセンス、SHA-256 を記載する。既存の軽量版へ取り込んで加入・複数表示・保存再開を確認し、同じパックの再導入と本体の更新後も重複や欠落がないことを確認する。公開許諾が取れた `.unitypackage` を GitHub Releases に添付する。添付ファイルは1件あたり2 GiB未満。 [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

## Unity 検証と公開判定

共有用 Unity プロジェクトは元の `C:/Users/hi-wa/unity_workspase/CatCafeSim` と別のフォルダに1つ作る。配置案はワークスペース内の `C:/Users/hi-wa/source/codex_repos/CatCafeSim/CatCafeSimLite`。共有用のファイルと新しい Git 履歴のルートを兼ねる。元の `Library` は引き継がず、以後の軽量版の確認にはこの1つのプロジェクトを再利用する。

軽量版では15件すべての発生条件と画像参照を確認し、各猫で承諾・見送り・会話途中の保存再開・回想を確認する。特にミケの20の分岐画像と、窓辺画像を共用するイベントの表示を確認する。

1. 採用するソースを固定して軽量版の許可リストを作る。許可リストから新しい履歴を持つ共有用ツリーを組み立て、`Assets` と `.meta`、`Packages` の manifest／lock、`ProjectSettings`、README、権利表示を収録する。初回コミットには元 `.git`、LFS 属性・ポインタ、原画、生成履歴、秘密情報、個人の設定・絶対パス、ログ、セーブ、キャッシュ、検証 Player を含めない。Unity と C# 単独版に必要なコードとデータを同梱し、Python や制作サービスを起動前提にしない。
2. Unity `2021.3.45f2` で、元の素材フォルダや LFS を参照できない共有用ツリーから取り込む。シーン／プレハブに Missing Script・Missing Reference がなく、収録カタログの全画像が解決することを確認する。外部の package GUID と Unity 組み込み GUID はインポート後に解決を確認する。検証ごとの Unity コピー・Library の蓄積は避け、同じ検証環境を再利用する。
3. タイトルから新規開始し、3匹が一覧に出ること、各猫の通常・交流・休憩画像、猫の切替と複数席、12枠の解放と来店、予約の承諾・見送り、満足・不満・常連化、閉店・翌日・収支、派遣と帰還、ミケの任意イベントと回想、各開始目標の達成を確認する。収録外の選択肢と猫が出現せず、イベント待ちで進行が止まらないことも確認する。1024×768／1280×800で日本語フォント、長文スクロール、画像の欠けを目視する。
4. 軽量版の `rules_id` と保存先を分け、`CafeProfile.Root` 配下の現行 `standalone-v1` と、設定・既読・回想・ギャラリーを共用しない。準備中・営業中・閉店後・イベントの選択後に保存し、再起動で状態が復元されることを確認する。元版セーブの自動読込や書き換えが起きないことを確認し、旧版インポートの対象外を README と UI に反映する。
5. Windows x64 の検証では `cat_cafe_sim_tool/build_standalone.ps1 -ProjectPath C:/Users/hi-wa/unity_workspase/CatCafeSim` を使う。軽量版の検証入口を追加する場合は `-ExecuteMethod` と共有の `StandaloneBuildStorage.Build` を使い、既存プロジェクトを検証に再利用できるよう元の未コミット変更と作業を分離する。出力は `Logs/StandaloneBuild/Latest/CatCafeStandalone.exe` の1組。ビルド中だけ `Pending` を使い、成功時に移動、失敗時は直前の Latest を保持し、ログを `Runs` に置く。起動と保存再開を Player でも確認し、ビルド ZIP は作らない。
6. 公開前に、コード・各画像・フォント・Unity 同梱物の再配布可否と必要表示を素材単位で確定する。元の [クレジット](../../Docs/Credits.md) と [第三者権利表示](../../Docs/ThirdPartyNotices.md) を起点に、ソース版・追加パックで実際に含むものへ合わせる。初回コミットのファイル一覧と全履歴を検査し、LFS ポインタや `filter=lfs` がなく、通常 clone で実ファイルを取得できること、100 MiB超のファイルがないことを確認する。GitHub 側の公開先・公開範囲は実行前に確定し、公開の承認後に作成・push・タグ付け・添付へ進む。 [GitHub の大容量ファイル制限](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)
