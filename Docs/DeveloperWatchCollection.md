# 収集を目的とした観戦プレイ

64倍速の回答待ちとエラー後の保存については [待機・保存の修正](DeveloperWatchRecovery.md) を参照。

開発用Playerで通常画面を操作し、内部収集検証と同じ担当表を使って猫・設備・用品・派遣を集める。既定の8日観戦はそのまま残す。

```powershell
.\cat_cafe_sim_tool\run_dev_watch.ps1 -Collection
```

「実行・再開」を押すと始まる。会話を読む場合は1倍・会話短縮なしを使う。ルートを限定する例：

```powershell
.\cat_cafe_sim_tool\run_dev_watch.ps1 -Collection -Routes collect-catalog-1,collect-catalog-2
```

|ルート|目的|
|---|---|
|popularity / patron / bond / free|人気・有力者・好感度の目標、または自由営業30日|
|collect-main|一度きりの紹介猫・購入猫、接客設備、席・休養・待合・飼育スペース|
|collect-dispatch|派遣先・派遣紹介猫・必要な特性の猫・用品|
|collect-catalog-1～3|紹介カタログを6系統ずつ分担|

ルートごとに新しいゲームと専用保存先を使い、完了時に次のルートを表示する。31系統を同時に飼育するものではない。全会話分岐・全画像・全専門/熟練の獲得は保証しない。

購入・猫の受け入れでは通常画面の候補を選び、費用と空き枠の確認を経て確定する。派遣・猫との交流も通常画面の操作を使う。内部検証から共有するのは判断と獲得判定で、別simulationの進行やゲーム状態の直接書換えは行わない。結果のlayerは `ui-handlers`、`physical_input_verified` はfalse。

保存・再開は通常観戦と同じ `-ResumeDirectory`。ルートはplanから復元する。`watch-checkpoint.json` はルート番号・セーブSHA・状態digestを持つ。ビルド変更前のcheckpointは再開できない。

保存先はrun配下の `routes/<route>/profile/standalone-v1`。完了結果は `routes/<route>/watch-result.json`、完了済みルートの和集合は `watch-collection.json`。未完のルートはpendingに残し、未到達項目を獲得済みに変えない。回想・画像は通常の閲覧記録を参照する。

結果の `operations` は、そのルートの保存完了時点におけるrun全体の通常コマンド累積値。各ルートの件数を足し合わせる用途には使わず、コマンドログのsequenceと照合する。

`image/rendered-gallery` は全画像の網羅を表す仮の項目なのでexcludedのまま。実際の画像閲覧キーは `watch-status.json` の `viewed_image_keys` を使う。

`-Speed 16` と `-Speed 64`、`-ShortDialogue`、`-Start`、`-ExitOnComplete` は高速検証向け。通常画面の速度ボタンは1・2・4倍。同じ進捗で120秒待機、合計100000コマンド、1ルート150日の上限で理由を残して停止する。
