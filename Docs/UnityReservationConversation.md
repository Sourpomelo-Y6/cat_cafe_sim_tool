# Unity単独版：特別予約のADV接続

2026-10-21。予約の導入、引き受ける／辞退する、回答結果、来店後の条件達成・条件未達・未接客を共通ADVへ接続した。

## 現行実装と旧資料

`Docs/UnityReservationAndTrust.md` はPython Session／HTTP接続版の記録。現行の標準起動は `LocalCafeBackend` とC#の `CafeSimulation` を使う。実装の正本は `CafeSpecialists.cs`、`CafeSimulation.cs`、`CafeCustomers.cs`。予約は人気第2段階の達成後、翌日の準備で一度発生し、来店日は依頼日の翌日。担当猫に `Rules.reservation.feature` があり、接客中の `open_up_count` が設定値以上なら達成。`connect_count` や同時達成回数を追加条件にはしない。

予約回答では資金・人気は変わらない。辞退のペナルティなし。受諾した来店当日は休業不可。追加料金は接客終了時、人気加点は閉店時（上限まで）の既存処理で反映する。条件・報酬・発生日・日程・抽選・成長・バランスを変更していない。新規画像、音声、実行時LLMは使わず、客アイコンと既存代替表示を使用する。

## 会話と進行

`CafeReservationDialogue.Lines` が本文の正本。実際の予約客の説明、依頼に対応する来店日・刻み、特徴ラベル、「心を開く」の必要回数、追加料金・人気加点を設定から表示する。未設定の来歴や発言、接客前の成功は創作しない。

- 導入：「{客名}から特別予約の依頼が届いた。{客の説明}」「来店日：{日}日目、来店刻み：{刻み}。担当猫の条件：{特徴}。接客中に『心を開く』{必要回数}回以上。」「条件達成時の追加料金＋{料金}、人気＋{加点}。引き受けた来店当日は休業できない。辞退のペナルティはなく、回答だけでは資金・人気は変わらない。」
- 選択前にも日程・条件・報酬・当日の休業不可・辞退の影響を表示。在店の健康な猫に指定特徴があるかを示し、出勤・体力等は猫一覧で確認するよう案内する。両選択で既存の最終確認と取消を維持。取消では回答・会話位置・資金・人気を変更しない。
- 受諾：「予約を引き受けました」「{日程と条件}」「来店当日は休業できません。回答による資金・人気の変化はありません。この回答結果を読了したら、営業や日程を進めて準備しましょう。接客結果はまだ確定していません。」
- 辞退：「予約を辞退しました」「辞退のペナルティはなく、資金・人気は変わらない。この予約による来店と追加報酬はない」「会話を終えて営業準備へ戻りましょう。」
- 接客結果：確定済みの達成／未達／未接客を明記。接客記録があれば担当猫・実際の「心を開く」回数・特徴条件の一致／不一致を示す。達成の追加料金と人気加点はそれぞれ接客時・閉店時の反映を区別する。営業中に経営終了した場合、閉店前の人気加点を反映済みとは書かない。未達・未接客では追加料金と人気加点なし。

通常は営業中に結果会話を開かず、他席・待ち行列・閉店の処理を進める。未接客は閉店直後に推測せず、既存処理が翌日の準備で `unserved` を確定した後に表示する。経営終了時は確定済みの結果だけを確認できる。未確定の結果を生成しない。

回答結果・接客結果が未読の間は次の営業・休業・日程・目標継続を止める。具体的な理由と「イベント一覧→特別予約→会話を終える」までの解消手順を既存の進行停止説明へ接続。受諾後の来店待ちだけでは進行を止めない。予約日の休業制限は読了しても残り、営業へ案内する。

共通 `AcquisitionConversationPanel` の最大3行ページ送り、文字速度、全文表示、次へ、バックログ、保存・読込、オプションを再利用。閉じた会話はイベント一覧の「特別予約」で再開でき、未読結果は「回答・会話待ち」に含める。成長とエンディングは予約結果の後へ戻し、他の共通会話との重なりは既存の排他制御を利用する。

## 保存・重複防止・互換

セーブの表示メタデータに `reservation_conversations` と選択IDを追加。案件IDは既存表示と同じ `reservation-{依頼日}`。会話本文の設定値、回答段階・結果段階の進行（節とページ位置）、読了分岐、接客詳細を保存する。ゲーム状態とリプレイの計算は変更しない。読込前に会話ID・対象案件・分岐・位置・既読との整合性を検証し、不正なら現在の営業状態を置き換えない。

回答は既存 `resolve_reservation` を通し、案件IDも照合する。既存のrequest ID、revision、読み込みによるepoch、送信中制限を使用。回答済みへの新規操作を拒否し、会話の閲覧・閉じる・保存・Extraから報酬や回答を再実行しない。

| 会話情報のない旧セーブ | 扱い |
| --- | --- |
| 回答待ち | 未読の導入から開始する |
| 受諾済み・結果未確定 | 過去の導入・回答会話は作らず、以降に確定する接客結果を観測する。来店待ちで営業を止めない |
| 辞退済み | 既存記録で辞退状態を確認できる。過去会話・既読・Extraを補わない |
| 結果確定済み | 既存記録で確定結果を確認できる。過去会話・既読・Extraを補わない |

初回観測後の新しい会話進行を保存した場合は、同じ案件の未読位置から再開する。既存セーブの報酬・日程を再評価しない。

Extraは読了した受諾、辞退、達成、未達、未接客の5分岐。回答分岐には導入を含め、接客結果は実際の確定記録を固定本文として保存する。途中で閉じた分岐は解放しない。各分岐の最初の代表記録を既存Extraへ登録し、案件台帳にはしない。回想は表示専用で予約・報酬・会話進行・日程を変更しない。
