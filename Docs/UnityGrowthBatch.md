# 営業後の成長集約と猫に合う自動決定

実施日：2026-10-19。対象：ワークスペース Docs/UnityUIFixRequests.md 項目8。前段1～7の説明欄復帰、一時停止中の回答、成長待ちを覆わないエンディング、3行ページ、上部配置を維持する。

## 確認と確定

- 営業中は成長実績と操作記録のみ増加する。成長待ちでは接客、自動割り当て、営業進行を止めず、選択画面も出さない。営業中の成長確定要求は拒否する。
- 閉店処理（接客終了、当日の休養回復、収支、目標判定）後に対象猫と成長事項を一覧表示する。右側の「自分で選ぶ」で仮選択、前／次で対象変更、または「猫に合う内容で自動決定」で未手動選択を埋める。自動選択後にも手動上書きできる。
- 内容と理由を確認し「一覧をまとめて確定」で現在の一覧を一括適用する。全件の合法性を先に確認する。未選択があれば一件も適用しない。確定後の再要求は拒否し、request_idとrevisionによる既存の二重送信防止も維持する。
- 1匹に複数段階がある場合は既存の優先順（得意分野→交流分類→個別行動）で扱う。確定で次段階が選べるようになった場合は新しい一覧を表示する。すべて解消するまで翌日／開店へ進めない。各一覧では複数猫を一括確定する。
- 対象は得意分野（接客／休養／派遣）、第1～第3の交流分類、それぞれの第1／追加個別行動。追加実績の開始条件・手動開始・接客開始時の自動開始は既存を維持し、未開始の実績や未解放段階を勝手に習得しない。習得済み／同分類条件に合わない／実績不足の候補は既存のMasteryChoices・TypeMasteryChoicesで除外する。
- 最大体力の自動成長は独立した既存機能。条件・経験・増加幅・上限・適用時点を変更しない。

## 自動決定の設計

すべて重み1の相対適性比較。ゲーム内の費用、効果倍率、経験、目標・売上、乱数を変更しない。毛色・毛長等の見た目は使わない。個性・特性は既存CatDefinitionに反映された好み・疲労／ストレス・回復・派遣係数を使用し、表示名から別の能力を推測しない。

| 選択 | 比較する値 |
| --- | --- |
| 個別行動 | 行動の好み × 対応する強さの好み（遊び＝活発、触れ合い＝普通、静か＝穏やか）。これは自動選択用の対応で、行動の強さを制限する設定ではない |
| 交流分類 | 分類に属する個別行動の適性の平均。行動数の多い分類へ加算で偏らせない |
| 接客分野 | 3分類の適性平均 ÷ 接客疲労・接客ストレス係数の平均（分母の下限0.01） |
| 休養分野 | 既存の休養疲労回復係数 |
| 派遣分野 | 既存の派遣報酬係数 ÷ max(0.01, 1＋帰還ストレス/100) |

同点順：接客→休養→派遣、遊び→触れ合い→静か、猫じゃらし→ボール→ぬいぐるみ→トンネル→なでる→ブラッシング→声かけ→そばにいる。候補を既存順で安定比較する。欠けた／非有限の好みは中立1。特性係数は既存定義の既定値を使う。全候補同点でも固定順で決まり、推定であることが分かるよう理由欄に基準・候補別スコア・同点順・欠落時の扱いを表示する。ゲーム進行用乱数を呼ばず、同じ定義と実績で同じ結果となる。

## 適用時点・他の進行との順序

- 当日の終了済み接客、売上、疲労回復、目標達成記録、派遣出発条件、履歴は再計算しない。接客の成長分類・個別行動は開始時の既存スナップショットを使う。
- 休業日：既存の休業決算を行い、成長があれば閉店状態で確認する。成長がなければ既存どおり翌日の準備へ自動遷移。成長確定後は「翌日へ」。休業コストは従来どおり。
- 準備中・派遣帰還：帰還確認で経験が確定した直後の準備画面で成長を確認する。次の営業開始や休業より先に確定する。閉店中の帰還も経験確定後に一覧へ追加する。未確認の帰還報酬を先取りしない。
- おまかせ：営業中は成長を通過し、営業後に同じRecommendGrowthと一括確定処理を使う。候補別理由はおまかせ判断記録と猫の出来事へ残す。停止／保存による一時停止中は手動・自動の仮選択と確定が可能で、回答だけでは再開しない。再開前には成長を解消する。中止しても成長実績・仮選択は残る。
- 目標達成・エンディング：成長一覧を先に解消し、その後にエンディング、結果確認、翌日へ。おまかせは同時発生した成長を先に確定してから目標達成による停止へ進む。経営終了時も成長確認自体は可能だが、既存の経営終了条件を解除しない。

## 保存と互換性

成長候補の正本は保存済みCafeGrowthの実績・習得済み状態とgrowth_operations。これから合法候補を再構成し、別の候補一覧との二重管理を避ける。仮選択はgrowth_selectionsへ猫ID・段階キー・選択・理由を保存し、ロード時に合法性を検証する。確定状態は既存の習得値・確定日・操作記録へ記録し、今回の理由もdecision_reasonへ保存する。

旧セーブの仮選択がなくても、成長実績から一覧を再構成する。旧営業中の回答待ちは接客を継続し、閉店時に確認する。旧閉店／準備中の成長待ちはその場で選べる。旧操作記録はgrowth_policy_version=0として旧即時タイミングで再生、新しい操作は1として集約タイミングで再生する。新しい省略可能項目が空なら既存ダイジェストへ含めず、旧記録を維持する。

## 残る課題・検証の範囲

- 同じ猫の依存する複数段階は一度に予測確定せず、段階ごとの一覧を続けて確認する仕様。追加実績の未開始段階を先取りしない。
- 長期の達成日・疲労・売上の比較評価は別作業。自動適性の重みは初期設計であり、プレイヤーの最適解や猫の好みそのものを保証する値ではない。
- 実画面の手動確認はWindows・1280×800。旧形式互換は実績からの復元と旧操作ポリシーで扱うが、全ユーザーセーブの全操作履歴を網羅した検証ではない。
- 既存の素材・名前・ルールJSON・文章カタログ等の未コミット変更は今回のコミットに含めない。Unityプロジェクトは既存UI修正等で元から作業中のため、正本のツールリポジトリだけをコミットする。ワークスペース直下DocsはGit外なので実ファイルを更新し、今回分だけの差分をDocs/Results/GrowthBatch/WorkspaceDocs.patchへ保存する。


## タイミング変更の影響

従来は営業途中の習得により、その日の後続接客で新しい効果を受けられた。今回は閉店後まで受けられないため、後続接客の関心や体力回復、早期の追加実績開始などが遅れ、達成日や売上に差が生じ得る。確定していない得意分野に依存する分類実績も既存の条件を維持する。これを補う追加経験、価格、補正倍率、費用、目標期限の変更は行わない。長期バランスの再評価は別作業。
