# コンテンツ制作ツール

動作を選んだ後、行動欄の「（なにか）+心を開く」「心をつかむ+心を開く」で特殊パターン画像を登録できます。追加は各動作で2種類だけです。発生時にその動作の特殊画像を優先し、未登録なら実際に行った通常行動の画像を使います。

場面選択では従来の4場面に加え、ねこじゃらし・ボール・ぬいぐるみ・トンネル・ブラッシング・声かけ・見守り・待機の画像を登録・生成できます。なでる画像は「撫でられる」を使います。交流別画像は登録したものをUnity向けに書き出し、交流画面で動作に合わせて表示します。動作を選んだ後に「行動」を選ぶと、強弱・フェイント・待機・切り替え・心をつかむを含む47通りの組み合わせ画像を登録・生成できます。未登録の組み合わせは動作の共通画像を使います。専用画像が未登録なら既存場面へ戻ります。

猫の目の色・体格・模様・顔立ち・尻尾・補足は「外見・行動・背景の設定…」で編集できます。詳細は [外見プロフィール](../Docs/CatAppearanceProfiles.md) を参照してください。

ゲーム本体と別のフォルダに置く、独立したPython/Tkinterツールです。背景込みPNGと紹介文・行動描写を猫ごとに確認・登録できます。ゲームの起動やSessionの生成は不要です。

親の `CatCafeSim` フォルダから起動します。

```powershell
python -X utf8 cat_cafe_sim_tool/run.py
```

猫と場面を選択 → 「画像を選ぶ…」 → プレビュー確認 → 「この画像を登録」の順に操作します。初期の猫一覧は隣のゲームの `config/cafe_playtest_cats.json` を読み込みます。独自の猫一覧や保存先も指定できます。

```powershell
python -X utf8 cat_cafe_sim_tool/run.py --catalog cats.json --output cat_cafe_sim/saves/content_images
```

猫一覧は `[{"cat_id": "cat-1", "name": "ミケ"}]` 形式のUTF-8 JSONです。ゲーム内の猫IDと一致させてください。ゲームデータを読み込むPythonモジュールには依存しません。

標準の出力先は `cat_cafe_sim/saves/content_images`。元画像をコピーし、`manifest.json` と `images/` を書き出します。この配置ならゲームの「猫の画像…」が自動で読み込みます。別の出力先を指定した場合は、フォルダの内容をゲームの標準読み込み先へ配置してください。

ゲーム側には画像登録ボタンを置かず、画像の読み込み・表示だけを残します。未登録・画像欠落時は仮画像になります。PNGのみ対応し、ゲームの数値やセーブは変更しません。表示用文章は、手動編集とローカルLLMによる案の生成に対応しています。

## ComfyUIで生成する

1. ComfyUIを `http://127.0.0.1:8188/` で起動します。
2. 制作画面で猫と場面を選び、「ComfyUIで生成…」を押します。
3. 接続先、モデル、seed、幅・高さ、Steps、CFG、正負プロンプトを確認します。
4. 「1枚生成」を押します。通信は別スレッドで動きます。
5. 完成画像が制作画面へ未保存候補として戻ります。気に入ったら「この画像を登録」で採用します。

ユーザーの `t2iSimple (2).json` を `workflows/t2i-simple-source.json` に保存し、その設定を初期値に使っています。API送信ではCheckpointLoaderSimple、CLIPTextEncode、EmptyLatentImage、KSamplerAdvanced、VAEDecode、SaveImageを組み立てます。画面編集用JSONの汎用インポート機能ではありません。

初期設定：`waiNSFWIllustrious_v140.safetensors`、1024×1024、27 Steps、CFG 7、`euler_ancestral` / `simple`。元のPrimitiveIntに接続されていた負のseedは使わず、非負のseedを直接指定します。基準画像を使うimg2imgと既存LoRAの適用にも対応しています。個体の完全固定を保証するものではありません。正プロンプトは下記の保存設定から組み立てます。ネガティブプロンプトは元ワークフローのものなので、猫には合わない制約も必要に応じて編集してください。

候補PNGと設定・実行seed・送信グラフ・ジョブIDのJSONは、ツール内の `generated/` へ保存します。Git除外対象です。ComfyUI側にも `CatCafeSimTool/cat` の接頭辞で出力を保存します。確認前にゲームの対応表を更新しません。生成中に猫・場面を変えた場合は自動で候補を紐付けず、保存先を案内します。

生成画面を閉じると結果の受け取りを止めますが、ComfyUI側のジョブは継続します。他のジョブを止めるAPIは呼びません。待ち時間上限は10分、各通信の上限は15秒です。失敗時は生成画面へ理由を表示し、再実行できます。

検証：GUIを含むテスト7件成功。起動中のComfyUIへ実際に通常猫の1枚生成を依頼し、PNGの取得と設定JSONの保存を確認しました。生成した候補は未登録です。

このフォルダはゲーム・資料とは別のGitリポジトリで管理します。既定ブランチは `main` です。リモートへの公開・pushは行っていません。

## 外見・行動・固定背景を保存する

1. 制作画面で猫と場面を選び、「外見・行動・背景の設定…」を開きます。
2. 外見、行動、背景、画風・視点・照明の文章を編集します。モデルへ渡す文章として、まず英語での入力を推奨します。
3. 「組み立てを確認」で、画風＋外見＋行動＋背景を確認します。
4. 「設定を保存」を押します。
5. 「ComfyUIで生成…」を開くと、選んだ猫・場面の保存設定がプロンプトへ入ります。生成画面で自由に手直しできます。

外見は猫IDごとに保存します。行動文は通常・遊ぶ・撫でられる・眠るの各場面で共有、背景と画風は全猫・全場面で共有です。行動文の変更は、同じ場面のほかの猫にも反映されます。

ミケには三毛猫の仮の外見、4場面には対応する行動文、背景にはシンプルな壁・床・マットを初期設定として用意しています。ほかの猫の未登録外見は一般的な猫の文です。名前だけで毛色を推定しません。実際の猫の設定に合わせて編集してください。

保存先はツール内の `user_data/prompt_presets.json`（Git除外対象）。ツール再起動後も利用でき、ゲームのセーブは変更しません。設定のバックアップはこのファイルを保存してください。設定が壊れていた場合は上書きせずエラーを表示します。

すでに開いている生成画面は自動で文章を上書きしません。「保存設定を読み直す」で現在の文章を置き換えるか、閉じて開き直してください。生成画面での一時編集は保存設定に反映しませんが、実際に送った文章は生成画像の設定JSONへ記録されます。

外見・背景を同じ文章にしても、絵の完全な一致は保証されません。基準画像を使う場合も、生成結果を比較して採用してください。

設定機能追加後の検証：GUIを含む11件成功。設定の再読込、個体別の外見、共通背景・行動の適用範囲、未設定時の代替、不正設定の保持、生成画面への反映を確認しました。この追加作業では新たな画像生成は実行していません。

## 基準画像から行動差分を作る

1. 猫を選び、「基準画像を選ぶ…」で通常状態のPNGを指定します。すでに通常画像をゲーム用に登録していれば「登録済み通常画像を基準に」も使えます。
2. 基準画像が左側に表示されます。場面を「眠る」などに変え、「ComfyUIで生成…」を開きます。
3. 「基準画像から差分を生成（img2img）」が有効になります。denoise（初期値0.65）を調整して生成します。チェックを外すと従来のt2iです。
4. 完成候補を右側で確認します。毛色・柄・体格・背景と行動を比較し、採用する場合だけ登録してください。

基準画像はツールの `user_data/reference_images/` へコピーし、猫IDごとに保存します。場面を変えても同じ基準を使います。登録・変更後は生成画面を開き直してください。ゲーム用の通常画像は変更しません。

添付された `i2prompt4 (1).json` は `workflows/i2prompt-source.json` に保存しました。元のワークフローにはWD14Taggerによるタグ抽出とdenoise 0.5・0.75のimg2img、およびt2iの比較があります。今回使うのはLoadImage → ImageScale → VAEEncode → KSampler → VAEDecode → SaveImageの単純なimg2img部分です。タグ抽出・回転・切り出し・複数結果の一括生成・IP-Adapterは組み込んでいません。元画像の座り姿勢をタグで再指定しないよう、保存した外見・行動・背景の文章を入力します。

基準PNGは `/upload/image` でComfyUIの入力フォルダへ送ります。指定した幅・高さへリサイズするため、基準と同じ縦横比を推奨します。出力の設定JSONには実行設定と入力画像のハッシュを記録し、隣に `.reference.png` として入力のコピーを保存します。

denoiseが低いと元の柄・背景を残しやすい一方、姿勢も残りやすくなります。高いと姿勢を変えやすい一方、柄・背景・画風が変わることがあります。これは同一個体を保証する仕組みではありません。

実機確認では、座った三毛猫を基準に「眠る」を生成しました。0.75では座り姿勢が残り、0.95と行動の強調では横たわる姿勢になったものの、不要な頭部の毛の表現や背景の差がありました。確認候補は未登録で、完成素材として採用していません。今後はプロンプトと強度の調整、必要なら別の参照方式を検討します。

差分機能追加後の検証：GUIを含む13件成功。個体ごとの基準登録、比較表示、生成への受け渡し、通常生成の維持、入力コピーと設定保存、実際のアップロード・img2img・PNG取得を確認しました。

## 既存のデザイン・ポーズLoRAを使う

1. 猫と場面を選び、「デザイン・ポーズLoRAの設定…」を開きます。
2. 接続先を確認し、一覧取得ボタンでComfyUIにあるLoRAを読み込みます。ファイル名を直接入力することもできます。
3. デザイン用・ポーズ用それぞれの有効チェック、ファイル名、MODEL／CLIP強度、トリガーワードを指定して保存します。
4. 生成画面を閉じて開き直し、適用するLoRAの一覧を確認します。
5. 「保存済みLoRAを適用」のチェックを入れて生成します。外せばLoRAなしで生成でき、同じseed・プロンプトで比較できます。

デザイン用は猫IDごと、ポーズ用は場面ごとに保存し、ポーズ設定は同じ場面の全猫で共有します。t2i・img2imgの両方でデザイン用→ポーズ用の順に適用します。トリガーワードは正プロンプトへ追加し、同じトリガー文字列は一度だけ追加します。トリガーを必要としないLoRAでは空欄にできます。

強度の入力範囲は-2～2、初期値0.7は仮の値です。使用するLoRAの説明に合わせて調整してください。一覧に表示されても、選んだCheckpointとの互換性や猫への効果は保証されません。モデル系列の互換性は利用者が確認します。生成前にファイル名の存在を確認し、見つからない場合はエラーを表示します。

設定は `user_data/lora_settings.json`（Git除外対象）へ保存します。未設定ではLoRAを適用しません。LoRAの重みのダウンロード・コピー・独自学習は行いません。独自LoRA作成は後回しとし、ローカル生成が難しい画像はChatGPT Imagesで作成したPNGを「画像を選ぶ…」から登録できます。生成結果の設定JSONには、適用LoRAとトリガーを含む送信グラフを記録します。

追加後の検証：GUIを含む17件成功。個体・場面別の保存、MODEL／CLIP接続、両生成方式への適用、トリガー、適用チェック、存在しないファイルの拒否を確認しました。起動中のComfyUIから70件のLoRA一覧を取得しました。猫向けLoRAを使った実画像の効果・相性はまだ確認していません。

## 紹介文・行動描写を編集して登録する

1. 制作画面で猫を選び、「紹介文・行動描写の編集…」を開きます。
2. 紹介文と、通常・遊ぶ・撫でられる・眠るの4場面の短い描写を入力します。画像生成用の英語プロンプトとは別の、日本語などの表示用文章です。
3. 作業途中では「下書きを保存」を押します。この時点ではゲームへ反映されません。
4. 「登録内容を確認」を押して確認欄で全文章を読み、「確認した文章を登録」を押します。確認後に編集した場合は再確認が必要です。
5. ゲームの「猫の画像…」で対象の猫を選びます。紹介文と、表示中の場面に対応する描写が画像と一緒に表示されます。自動表示中は登録内容の更新も反映されます。手動表示中は場面の選び直しなどで更新されます。

文章は猫ごとに独立して保存します。開いた編集画面の猫は固定され、親画面の猫を切り替えても編集対象は変わりません。別の猫を編集するときは編集画面を閉じて開き直してください。登録は対象の猫の紹介文と全4場面をまとめて更新します。空欄にして登録すると、その欄はゲームの定型文に戻ります。紹介文は2000文字以内、各行動描写は500文字以内です。

下書きは `user_data/text_drafts.json`（Git除外対象）、登録済み文章は画像出力先の `texts.json` に保存します。標準では `cat_cafe_sim/saves/content_images/texts.json` です。画像の `manifest.json` と別ファイルなので、画像の登録状況にかかわらず文章を利用できます。別の `--output` を使う場合は `texts.json` もゲームの標準読み込み先へ配置してください。

編集画面を開くと下書きを優先し、下書きがなければ登録済み文章を読み込みます。登録ボタンは登録済み文章だけを更新するため、編集途中の下書きが残っている場合は開き直すとそちらが表示されます。採用した文章を次回の編集の起点にする場合は、同じ内容で下書きも保存してください。壊れた保存ファイルは上書きせずエラーを表示します。ゲーム側は未登録・空欄・読込失敗時に定型文を表示し、文章を書き込みません。

保存形式はUTF-8の版付きJSONです。猫IDと場面キーは画像と共通で、Unity側でも読み込める形です。

```json
{
  "version": 1,
  "cats": {
    "playtest-mike": {
      "introduction": "好奇心いっぱいのミケです。",
      "scenes": {
        "normal": "マットの上でくつろいでいます。",
        "play": "おもちゃを追いかけています。",
        "pet": "撫でられて目を細めています。",
        "sleep": "丸くなって眠っています。"
      }
    }
  }
}
```

検証：制作ツールのGUIを含む19件とゲーム側の関連8件が成功しました。下書きの再読込、未確認文章の登録拒否、猫別保存、ゲーム画面表示、空欄・不正ファイルの代替表示、既存の自動切り替えを確認しました。

## ローカルLLMで文章案を生成する

1. 猫を選び、「紹介文・行動描写の編集…」を開きます。
2. 「ローカルLLMで文章案を生成…」を押します。
3. 接続先（初期値 `http://127.0.0.1:8080`）を確認し、「モデル一覧を取得」でモデルを選びます。末尾 `/v1` 付きのURLも使えます。モデル名の直接入力も可能です。
4. 猫の毛色・柄・体格・性格などと、文章の雰囲気を入力します。画像や画像生成プロンプトは自動送信しません。
5. 「紹介文と4場面を生成」を押し、生成案を確認します。
6. 採用する案であれば「この案を編集欄へ取り込む」を押します。紹介文と全4場面の編集欄が置き換わります。
7. 必要に応じて手直しし、既存の「下書きを保存」「登録内容を確認」「確認した文章を登録」へ進みます。

生成画面を開いた時点から編集欄が変わった場合は取り込みを拒否し、編集中の文章を保護します。その場合は編集内容を保存し、生成画面を閉じて開き直してください。生成案を取り込んだ後も登録前の確認が必要です。失敗時は既存の編集・下書き・登録済み文章を変更しません。

日本語の短い紹介文と4場面の描写を、簡素な固定背景・汎用の手・猫を主役にする条件で依頼します。JSONの形式、4場面の有無、空欄、文字数を検証します。ただし、事実との一致や日本語の自然さ、画像と描写の一致は利用者が確認してください。独自の外見や背景が勝手に追加されていないか確認して採用します。

通信は別スレッドで実行します。一覧取得は15秒、生成の応答待ちは180秒が上限です。閉じると結果の受け取りを中止し、サーバー全体を停止するAPIは呼びません。サーバー側の生成は継続する場合があります。

有効な生成案と、接続先・猫ID・モデル・入力・API応答を `generated/texts/<UUID>.json` に記録します（Git除外対象）。これは生成の記録であり、下書き・ゲーム用文章の登録ではありません。接続先・モデル・特徴・雰囲気の入力は生成画面を閉じると初期値へ戻ります。必要な入力は生成記録から確認できます。

実装は[llama.cppサーバーのAPI仕様](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)に沿って、`GET /v1/models` と `POST /v1/chat/completions`（非ストリーミング・JSON形式）を使います。認証なしのローカルサーバー向けで、APIキー入力やOllama専用APIへの切り替えは未実装です。

検証：GUIを含む23件のテストが成功しました。モデル一覧、生成JSON検証、出力中断・不正応答、生成記録、確認後の取り込み、編集中の文章の保護、手動編集の維持、画面終了時の受け取り中止を確認しました。起動中の8080番のGemmaで日本語の紹介文と4場面を実際に生成・取得しました。確認候補は下書き保存・ゲーム登録していません。

## Unity向けに素材を書き出す

「Unity向けに書き出す…」で保存先を選ぶと、新しい `CatCafeContent-<ID>` フォルダを作成します。猫一覧と採用済みの紹介文・4場面の描写・PNGを、`bundle.json` と `images/` にまとめます。下書き・生成候補・基準画像は書き出しません。同じPNGはハッシュでまとめ、未登録文章は定型文、欠落画像は画像なしで書き出します。確認事項は結果画面と `validation.json` に記録します。以前の出力は上書きしません。
